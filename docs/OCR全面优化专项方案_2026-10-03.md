# OCR 全面优化专项方案（2026-10-03）

推荐路线：**先分清读取与绑定损失，修复候选/裁剪契约，再分别微调文字检测器与识别器，最后用真实器件和引脚上下文选择字段。** 保留 PP-OCRv6 medium 开发候选为主线；不从头训练、不一次替换全部模型。最终目标是提高严格输出中的正确位号、型号、参数、引脚编号和名称，并使网络质量不退化。

本方案重新检索了原理图案例、OCR 原论文和官方训练文档，结合本次本地代码检查及新到的 cycle80–95、全模块第一阶段报告。服务器原始产物本次未远程读取或重跑，报告事实与本次直接检查分开列出。以下任务全部是拟定实施计划；数值门槛是开发验收建议，不能解释为预期收益承诺。

**三、先建立真正能回答“是否需要训练”的诊断（O00、O01）**

冻结生产Bprod和开发Bdev79的模型、代码、有效配置、字符表、预处理、静态库、输入manifest及评估器。当前服务器候选补丁与本地源码不同，迁移前做diff；不把文件名中的版本号当哈希。

每个实际观察保存image/group ID、view、原图polygon、local_to_global、crop像素哈希、det/rec参数、原文、候选及分数、合并来源、角色/owner决策和拒绝原因。在现有Circuit-IR的Evidence/metadata中扩展，不增加第二套领域实体；官方JSON不输出这些诊断。异常、超时、空结果、阈值拒绝必须分开。

阶段状态至少有detected、geometry_accepted、recognition_attempted、recognition_accepted、deduplicated、role_assigned、owner_assigned、serialized。读取失败不能把之前的文字检测TP删掉；视图batch trace按图累计且不串图。当前ONNX infer_bgr过滤空识别后才返回，后续trace只有结果数，须补原始框与拒绝阶段数据。

离线建立四个受控实验，GT仅由诊断进程访问：

| 对照 | 保持与替换 | 能回答什么 |
|---|---|---|
| D0真实路径 | 预测框+真实裁剪+当前识别器+真实绑定器 | 完整基线 |
| D1读取能力 | GT/人工核验完整文字框裁剪，识别器不变 | 合理crop仍读错时，优先微调识别器；不能作为生产预测 |
| D2绑定上限 | GT文本和文字框，器件/pin仍为预测几何，运行真正association | 文字正确后，真实几何与绑定还损失多少 |
| D3几何依赖 | 在D2中进一步用GT器件/pin几何，仍实际运行绑定 | 分清pin漏检/错位与绑定规则损失 |

D1–D3全部标记oracle=true，不直接返回GT owner，不进入正式预测/晋级。D0与D1差距包含检测、crop分布等联合影响，不能机械归因给单一模块；再用固定框的crop实验隔离。

按字段、原图字高（建议≤8、9–12、13–20、>20px）、长度（1、2–3、4–8、≥9字符）、方向、遮挡、密度分层。桶界仅作初始诊断设置。检测用一对一文字框匹配；识别用原始exact和CER；同时报告GT文字覆盖不完整的区域，未匹配预测不能一律认定FP。

每轮审查约100个真实失败区域，首先判断可辨认性与标注一致性。只在训练分区修订版本化监督；开发GT疑点单独出具报告并保留主指标，不能为候选临时屏蔽错误。

**四、数据方案：让检测、识别、绑定各自拿到正确监督（O02）**

训练仅使用dataset300-v2的train240。复用服务器已有214拟合/26内部检查的准确manifest及原group，不能随意按图片数量重新切。26图已经被反复调参使用，且祖先模型可能看过其中图片，明确称开发检查集，不能宣称独立验证。若建立新内部校准划分，要追踪祖先权重暴露和设计组，不能靠重新划分获得“独立”标签。

val30/test30/release50均保留暴露记录，不进入训练。新10GT只能作版本化回归参考：历史使用不确定，108个∅/Ø前缀器件key的视觉语义、类别映射仍待确认；它不是训练集或独立holdout。[10GT审计](E:/EDA挑战题目六/docs/server_updated_10gt_audit_2026-10-03.md)

三种训练记录分别维护：检测记录=图像/ROI+完整文字polygon+ignore区域；识别记录=实际crop+可见原文转录+截断/方向/字高；绑定记录=预测文字/几何候选+离线监督role/owner。识别器可以用核验GT文本作监督；绑定器输入必须保留实际OCR错字，不能用GT原文或owner替换输入。

一个GT目标的global/ROI/strip/scale2重复观察共用target_group_id，采样权重归一，不能当独立目标反复计数。正确识别目标覆盖、观测命中次数、最终正确字段三个数字分开统计。监督歧义masked，有效负例必须经覆盖审计；OCR未标注区域不能默认无文字。

首先整理至少5000个有效识别裁剪作为工程起步目标，优先覆盖小编号、型号与长pin名；具体可用数量经审计决定，不承诺5000条就够。增强只来自train240派生：轻度缩放/模糊/压缩、线宽和对比度扰动、裁剪边缘偏移。严重遮掉字符时不能继续使用完整字符串作真值；重新标注可见串或排除。禁止镜像字符、随意删小数点/下划线、大小写统一化。首轮不引入外部合成文本训练库或新数据集。

**五、检测与裁剪：小编号和完整文字行分别优化（O03、O04）**

复用现有global/component/side_strip调度，在缺字段或冲突时增加有界补看：位号看器件外邻域，编号看pin侧边，型号/长名称看完整内部行。小单字符可由局部连通域、已观测pin行和字高提出补充crop，再交识别器确认；不沿pin次序生成数字。

先固定模型做有限单因素对照。以有效配置为基准，像素阈值可试基准±0.05，框阈值基准±0.1，unclip基准的0.8/1.2倍并限制合法范围；这些是搜索邻域建议，不是最优值。先选一个主因，再试最多两种替代，不运行全组合网格。阈值下降导致线噪声显著增加时，改局部触发与监督，而非继续全局放宽。

检测训练仅在D0/D1与原始框trace证明确实漏文字后启动。检查DB收缩目标是否使细小单字符消失、ignore是否误覆盖、细线负例是否充分；此项是审计假设，尚未认定为当前bug。保留真实尺度分布，同时增加困难小字ROI采样；同一训练图的多ROI仍属于一个group。

裁剪实验必须保存准确像素：原四边形矫正为基准，对照少量按字高比例扩边（例如每侧0/0.1/0.2倍字高）、方向重识别和完整行crop。扩边不得吞入邻行/器件外框；坐标用正确变换回原图。0/90/180/270旋转只对方向不确定crop触发，核对当前自动竖图旋转，防止重复转向。

本地识别器最终归一到48高；同一crop先2倍放大又缩回48，不一定提供新信息。必须分别报告“放大改变检测/裁剪”与“固定crop改变识别”的收益。改变识别高度、最大宽度或padding协议需要模型/export/adapter共同支持，不能仅修改一个常量。

对于断裂文字，依据相邻框、基线、字高和原图提出完整行候选后重读；不直接把若干字符串拼成字段。对于1/11、2/12，必须看原图笔画和裁剪是否含导线，不能偏好较长结果。暂不继续已有无收益的同款直线擦除实验。

**六、识别训练：主线微调medium，备选模型后置（O05、O06）**

目前训练涉及三类不同模型：旧Torch OCR负责检测/读字；PP-OCRv6 medium是开发候选读字模型；小型role/owner模型负责字段解释。重训第三类不能代替微调第二类。`torch_train_cli --task ocr`当前实现也不能直接训练PP-OCRv6。

实施前核验对应Paddle版本、训练源码commit、medium训练checkpoint、字典索引、CTC/辅助头、许可证及导出链。本地仅有ONNX时，不声称可直接恢复训练；先确认可获得匹配的训练资产，再在独立环境做桥接。不得覆盖`.venv-train/.venv-test/.venv-yolo`既有职责，不自动升级基础框架。若资产缺失，继续裁剪/候选/绑定工作，并明确训练子任务缺项。

第一轮只训练识别器，检测器固定；下一轮需要时才训练检测器。建议方案如下，均需smoke决定实际参数：

| 项目 | 起始实验设计 | 约束 |
|---|---|---|
| 初始化 | 匹配版本medium训练权重，字典不变 | 不从零训练、不用ONNX冒充训练checkpoint |
| 更新范围 | 先试低学习率全模型微调；退化/样本少时再试冻结早期backbone | 两者是独立实验，避免同时改变采样 |
| 学习率 | 首轮1e-5量级，最多再试3e-5量级；先检查梯度/预训练配置 | 工程搜索建议，非官方v6最优值；按有效batch和优化器复核 |
| batch | 先32，按显存与变宽padding调整，必要时梯度累积 | 记录有效batch，识别长度分桶；不为填满显存扩大规模 |
| 轮次 | 首轮最多10–20轮，开发指标连续3–5次无提升则早停 | 首轮smoke单独产物，不算候选验收 |
| 损失 | 复用该版本的官方训练损失/辅助头配置 | 先检查CTC有效长度、相邻重复字符所需步数、非有限值、空标签；不盲删辅助头 |
| 采样 | 先自然分布基线，再试困难字段2倍且按目标去重封顶 | 不同时改学习率；总体和各字段分开看 |
| 精度 | FP32 smoke，支持且有限梯度验证后使用混合精度 | 比较未缩放梯度、解码和导出差异 |

选模以原始字符串exact为主、CER为辅，短编号/型号/长pin名及大小写/符号单列。总体CER降低但引脚编号exact下降，不通过。通用能力保持通过同一train来源的常规字段回放监测，不加入被禁止的外部训练集。只保留best与必要resume，不堆积所有epoch权重。

O06为条件分支：若正确crop下medium微调仍系统性失败，选择SVTRv2或PARSeq之一做同crop、同训练来源、同导出/时间口径的对照。不能根据不同论文榜单数字直接选胜者。首先比较单模型，不默认常驻双识别器；若只在少量难例互补，再设计有预算的第二识别调用。

缩小字符集或训练数字专用头后置：它可能不支持EP、A1、特殊编号和符号。先保留原字典做领域微调。任何字典变更都必须同步输出头、label encoder、CTC blank索引、解码器及资产哈希，未见字符明确计OOV，不静默替换。

**七、候选选择：保留视觉假设，避免重复观察投票（O07）**

本地ONNX为greedy，Torch已有beam，因此不能把配置`recognition_candidate_count=5`视为ONNX已输出5个候选。先在ONNX实现少量按需序列候选，绑定每个candidate的真实序列分数、crop、polygon和预处理版本。它们来自模型视觉概率，不通过正则自由生成。只对低间隔、缺关键字段、角色冲突crop触发，默认k=3与k=5对照；CTC聚合路径正确处理blank/repeat，不用字符top-k笛卡尔积冒充序列beam。

多视图合并基于同一物理文字的位置、重叠、字高、方向与跨度，不能只按相同字符串/中心距链式合并。不同位置的R1是两个观察；同一位置的global/strip不是两票独立证据。输出文字必须对应实际选中的成员框，而非组代表框。当前casefold去重保留了被抑制原文，但大小写变体不一定进入可选择列表，先测其造成的exact损失，再补候选传播。

固定分组下比较raw候选top-k覆盖、分组后覆盖、实际选择exact，全部一对一、同一候选同时满足位置与文字条件；不能用远处成员的正确文本解释近处框。历史单图分组损失仅作回归，不能当最新全量瓶颈比例。

角色、owner、识别分数分别校准；不同backend原始置信不能直接取最大。识别平均字符分数需按长度/角色检查可靠性，不能把0.9999当字段正确率。输出保留raw_text与selected_text及证据，大小写/空格原文不静默改写。

**八、联合绑定：从“文字到最近pin”升级为受约束的可拒绝选择（O08）**

复用现有Hungarian/单调DP，在候选评分中联合编号、名称、器件主体边、真实pin行和邻近竞争对象。一个观察至多承担一个冲突角色，容量按实际字段合同配置；同一pin可同时拥有来自不同可见文字的name与number。允许unknown/未绑定，不使用强制全匹配。

先区分“目标pin不在预测池”和“pin在池里但选错”，前者交给pin模块，不能将一个编号硬分给最近的错误pin。显式owner只对可靠来源作强约束，早期学习结果不自动升级为不可更改的权威。全局前缀限制、静态型号库扩展已有退化记录，不再直接重跑。

网络结构可作推理时的歧义特征或拒绝信号，但不能用预测图的错误连线反推并编造编号。冻结感知回放必须保存stable internal_id和字段前后差异，列出被救回、误激活、原有正确pin丢失三类对象。固定共同pin上的拓扑与全量拓扑同时报告；cycle91丢失6个TP与对象删除有关，不能只检查共同pin。

沿用已有“改变字段精度≥98%、至少20个已标注目标”的内部开发门槛，不放宽门槛；新增风险说明：20个即便全对也不能证明总体精度98%。同步报告唯一目标数、图/group数及区间，检查支持量不足的类别；验证分数不得作为模型概率。端到端首轮还要求原有正确位号/编号不退化、连接TP不下降、FP不增加。若需要权衡，保留候选报告，不自动晋级。

**九、运行时、训练出口与模型锁（O09、O10）**

服务器T13已验证fast_exact在8视图5轮配对上的OCR批中位下降11.59%，80次输出字节一致；这是局部OCR结果，不是整图收益。该候选默认reference、可回滚，后续直接核验并复用，避免重新实现。保留全量概率有效性、非获胜位置NaN/Inf等合同。

当前已有按宽高比排序；新的性能工作是审计跨ROI合批、重复crop缓存和设备复制是否有额外收益。缓存key包含像素、形状、模型、字典、预处理及解码参数；错误/超时不能缓存成永久空识别。跨ROI合批改变padding可能改变输出，必须检查单crop与batch结果、排序确定性和最终JSON。

GPU端输出索引/分数与有效性状态、I/O Binding须在profiling证明瓶颈后实施；图导出修改属于新模型资产，需要版本与一致性验证。整条流水线按图600s、批次有效配置7000s（若基线仍如此）验收，不引用7200s掩盖更严格执行配置。GPU训练和正式推理测量排队，单GPU串行，运行前核对资源与lease。

medium微调模型导出必须核对原框架与ONNX在短数字、长串、空crop处理、竖排、不同宽度、batch、非连续输入等上的差异。识别模型改善允许与旧模型输出不同；“数值/字节等价”是同一候选不同后端或纯性能改动的要求，不能要求新训练模型与旧模型完全一致。

打包模型、字符表、预处理descriptor、训练/数据lineage、评估、导出一致性和许可。PP训练结果不能绕过现有bundle契约；先实现/验证其到候选bundle的桥接，生产推理仍使用既有ONNX适配路线，不引入Paddle为强制生产依赖。任何新增role权重也需追踪。由model_promotion生成新锁，不手改blessed/status。

**十、实验矩阵与验收门槛**

下列提升幅度为首轮筛选目标，尚无实测收益；既有更严格门槛继续有效。所有比例以唯一字段目标计数，同一图多crop不独立采样。

| 实验 | 固定项 / 改变项 | 局部门槛建议 | 全链路要求 |
|---|---|---|---|
| E0诊断 | 原模型/配置，增加trace和oracle离线对照 | 每目标损失路径可追溯，所有分母闭合 | D0输出不变 |
| E1裁剪 | 模型固定，只改一种crop/方向策略 | 难例exact提高≥3pp，常规字段下降≤1pp | 正确位号不下降；新增字段来自原图 |
| E2小字检测 | rec/绑定固定；后处理或det微调二选一 | 小编号检测recall提高≥5pp，已审查区域precision下降≤1pp | 最终正确编号增加且网络不退化 |
| E3识别微调 | 固定crop、字典、det/绑定 | 编号/型号/长名目标桶exact提高≥3pp；整体不退化 | actual crop评估及字段+owner改善 |
| E4候选选择 | 权重/观测固定，改分组/解码/选择其一 | 正确候选保留率上升，错误接受不增 | 引脚存活与网络一起验收 |
| E5联合绑定 | 图像观测固定，只改role/owner策略 | 既有98%改变字段精度和支持量要求；报告区间 | TP不降、FP不增，逐例解释 |
| E6性能 | 质量算法固定，改缓存/CTC/batch | 5轮交替配对，建议中位耗时下降≥10% | 纯性能变更最终JSON字节相同 |
| E7组合 | 只组合通过局部与回放门槛的分支 | 5图定位→val30开发回归 | fresh四模型、严格输出、预算、lineage完整 |

改变字段精度 = 改变后正确的可评价唯一目标 / 全部改变且可评价的唯一目标；另计新增、覆盖、删除和unknown，masked不能从失败中临时挑选。报告每字段raw exact、CER、exact+role+owner、可用组件/pin留存、raw-v1四项、guide-v1本地回归、strict/degraded/fallback比例。官方evaluator仍未获得，正式成绩记未测。

统计以图或原设计group配对bootstrap为主，附每图明细；30图反复调参产生的区间不代表独立泛化。模型训练获胜设置再复核第二个seed；不做大规模seed或全参数搜索。单一假设两轮无有效增益即归档，不继续刷开发集。
