# 大模型训练与轻量 OCR 字段分类进展

本轮完成了一个仅 48,119 字节的 OCR 字段分类候选。在同一批 30 张验证原图的冻结感知对照中，最终型号精确匹配从 8 增至 11，引脚名从 189 增至 192，其他字段及四项 raw-v1 代理指标保持不变。YOLO11l 正式训练已经结束，YOLO26l 仍在训练。生产锁没有晋级，器件、引脚、网络、线段四项均达到 95% 的目标尚未满足。

## 1. 比较口径

训练只使用 dataset300-v2 的 240 张 grouped train。验证用已有 30 张 grouped val；它们已经用于开发诊断，不是独立泛化测试。官方评测器尚未获得，下面的 raw-v1 结果不是官方 ComponentF1、PinF1、NetHypergraphF1、NetLineF1，更不是竞赛成绩。

本轮固定此前 PP-OCRv6 medium 感知结果、器件/引脚/线段坐标、流水线配置和静态器件目录，重新运行 association → graph → nets → validation → output。候选新增字段分类推理；并未重新推理四个感知模型。对照复用周期 14 已闭合的控制产物，该控制此前已验证与服务器 medium 基线 30/30 官方 JSON 字节一致。本轮又核对了其文件哈希、聚合及逐图 raw-v1 结果。

候选 30/30 图输出成功，严格 Validator 为 0 ERROR，30/30 输出可重复序列化为相同字节。文件访问审计没有 GT/sidecar 访问，图像、配置、输入感知和运行源码哈希未变。30 张仍全部属于 `degraded_nonempty`，不能将“合法输出”理解为“高准确率”。

## 2. 轻量 OCR 字段分类

采用纯 NumPy 线性 softmax，输入包括可见文字的字符 n-gram、字符形态、文本框及附近器件/引脚几何关系，共 2,078 维。类别为 designator、value、searchname、pinname、pinnumber、netlabel。训练特征没有使用目标字段值、GT owner ID 或目标引用 ID。缺少字段标注的 15,652 条文字被排除，没有作为“其他”负样本。

在 240 张 train 内部按图分出 216 张拟合、24 张内部验证，内部验证选择第 39 轮：accuracy 92.49%，macro F1 89.59%。这只是训练内部的字段分类结果，不代表器件/引脚/网络/线段准确率。候选权重仅保留一份，48,119 字节，SHA256 为 `f772f0d569e3d211d3c3c1297c6ab3a0d556cb7aa72502f2d2d611c3b3c71078`。

推理采用预先固定的概率 ≥0.95、第一第二类别差 ≥0.30 门槛，只修复 searchname、pinname、pinnumber。引脚号必须来自实际数字文字且靠近已有预测引脚；型号需要已有器件框与独立可见参考位号支持。候选不创建器件 key、引脚号字符串、坐标或新 owner。

39 次字段修复中，29 次转为引脚名，10 次转为型号。预先定义的“聚合指标无退步且至少一项改善”开发门槛通过；这只支持保留候选继续开发，不支持生产晋级。

逐图差异必须保留：0044 型号 0→2，0171、0291 各 0→1；0190 引脚名 21→23，0202 为 15→16。0135 的型号精确匹配 1→0。单独的离线 GT 审计确认：0135 的目标 searchname 是“IO0:低电平下载，高电平运行”，控制输出相同，而候选选择了图上的“ESP-12F模块”标题。这个差异涉及标题、功能说明与型号的语义边界，不能仅凭肉眼将候选判作正确，也不能把计数下降隐藏或改写标签。该审计没有进入推理，也没有修改产物或阈值。

当前最大缺口依然是器件/引脚覆盖和网络连通。字段分类器的小幅提升无法弥补大量漏检、被裁剪 owner 以及引脚号缺失。

## 3. YOLO11l、YOLO26l 与磁盘保留

YOLO11l 已完成 67 轮正式训练，正常退出。34 类模型共有 25,336,694 参数，使用相同的 640 输入、batch 8、240 原图训练派生的 1,417 tiles 和 30 验证原图派生的 190 tiles。候选 AMP 检查未通过，实际运行 FP32；不能仅依据配置中的 AMP 开关宣称半精度训练。

YOLO26l 在不可变快照 `2026-10-02T05:57:04Z` 已完成 32 轮，训练进程仍存活。YOLO11n / YOLO11l / YOLO26l 的同一批 30 张完整原图对照已经排队，等待既有训练序列结束后串行执行。尚无这组三模型的原图比较结果，因此不能宣称更大模型或 YOLO26 更好。

已确认 YOLO11l 训练进程结束、最佳权重和报告哈希正确后，删除这次实验新生成且后续比较不使用的 `last.pt`，回收 51,248,914 字节（约 48.9 MiB），保留 `best.pt`。此前两项 smoke 的四份无用权重已回收约 199 MiB。当前活跃训练和比较仍需要的权重保留，不额外下载其他大模型；没有重新尝试此前被策略拒绝的清理目标。

## 4. 真实线掩膜的性能验证

周期 12 的局部函数微基准不能证明整图时延。本轮在服务器隐藏全部 GPU，以当前锁中的 wire 模型进行 CPU 分割，再对完全相同的实际掩膜比较原始和优化后的完整向量化过程。比较覆盖线段、交点、坐标恢复、去重和修复元数据，只有最近连通块点对搜索函数不同。

0030 单图预检通过：完整内容字节相同、输入掩膜未变，CPU 向量化耗时 31.37→4.30 秒。30 张全批对照在上述快照时完成 7 张、仍在运行。这个单图 CPU 结果不代表 GPU 整图 P95，也不能证明单图 600 秒、全批 7,200 秒预算已经满足。优化源码仍放在实验目录，未修改服务器生产源码。

初次探测仅因诊断 JSON 不能编码 `RepairRecord` 失败，失败日志保留；v2 使用完整 dataclass 编码后预检通过，没有删减几何或证据字段来获得一致性。
