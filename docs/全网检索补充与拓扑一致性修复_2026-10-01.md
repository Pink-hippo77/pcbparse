# 全网检索补充与拓扑一致性修复

核对日期：2026-10-01。验收目标仍为 **ComponentF1、PinF1、NetHypergraphF1、NetLineF1 四项分别 ≥95%**。官方 evaluator 尚未获得。

**有值得进一步试验的方法。当前最有价值的组合是：成对几何评分改善文字归属，器件内编号/名称联合匹配，去文字后的骨架端点辅助可见引脚检测，以及区分交叉类型的连接重建。** 本次检索还补充了轻量关联方法和复杂 PCB 的多模态评测证据，没有找到在本赛题同一口径下证明四项分别达到 95% 的可直接替换系统。

本轮已经修复一个实际工程瓶颈：精确重复线段去重丢失折线来源，导致建图与严格验证不一致。修复后 30 图及其重复回放均为严格 Validator **0 ERROR**；输出与修复前逐字节一致。这是有效性与可验证性的改善，**没有提高识别准确度**。

## 指南决定应优化什么

本地[赛题指南](E:/EDA挑战题目六/artifacts/reference/2026_EDA_Challenge_Task6_AI_PCB_Schematic_Official_Guide.pdf)第 6–8 页规定四项权重为 30%/25%/35%/10%。Component 依 key 匹配，并要求类别、框与必要文本正确；Pin 先依 component key、再依 number 匹配，同时检查名称与 5px 坐标误差；NetHypergraph 按 pin set 匹配；线段仅在匹配网络内按两端点检查。因此，位号、编号、归属错误会继续影响网络和线段，不能只追求检测 mAP 或导线像素指标。

指南第 5 页规定全批小于 2 小时，正式案例为 30–50 张；当前可执行配置另设单图 600s。50 图的平均硬预算为 144s/图，还须计入共享加载、调度和写盘。论文速度、局部 CPU fallback 耗时均不能作为目标容器 GPU 全批证据。

## 本轮已完成的工程修复

只读诊断发现 20/30 图共 352 个 `NET.DISCONNECTED_SEGMENTS`。去重后的 canonical segment 只保留一条 `source_polyline_id`，原始相同线段来自其他折线的转角来源被丢弃。将原始连接证据按精确重复线段映射后，352 个网络全部连通；未发现丢失的共线连接，原先的共线顺序假设未成立。

实现增加 Circuit-IR 内部 `source_polyline_ids`，仅在**精确同通道、同端点**去重时保留已观测来源的排序并集；建图器与验证器共享该并集，并继续执行原有端点接触检查。未增加距离容差，没有添加线段、修改 pin 坐标或伪填 key/number。同步更新离线 oracle 来源清除逻辑，避免新字段残留 GT membership。

生产 `degraded` 执行已取消将质量 ERROR 改成 WARNING 的通道。建图前的无身份对象裁剪仍保留；真正的断连或 junction 错误继续阻止 Serializer。

## 接下来的完整实施方案

|顺序|实现工作|对照与采用门槛|
|---|---|---|
|P0：身份与文字归属|器件 ROI 上下文单独加默认关闭的配置；联合编号、名称行、方向与可见型号。比较现有几何评分与成对评分，复用 Hungarian/有序 DP。|各字段与 owner 分开计数；现有 +58 名称收益必须在完整原图重现。编号、位号、真实连接 TP 不下降，连接 FP 不增加；缺身份继续拒绝。|
|P1：可见引脚候选|保持原图 OCR；另建保守去文字线条视图。骨架端点、器件边缘穿出短线与 Pin 热图共同提候选。|先做纯候选增益，再做绑定后增益；按 5px、owner、number/name 联合核验，观察最终裁剪损失。不整框清空、不补造库中不可见引脚。|
|P1：网络与线段|逐项处理文字/边框污染、交叉类型、跨线桥、平行线竞争及局部有证据缺口。保留完整物理与电气网络区别。|匹配同一组最终网络成员与网络内端点；每个桥接记录图像证据。相同明确信号标签可作逻辑连接，AGND/DGND/PGND 不因同属 GROUND 合并。|
|P2：必要的学习对照|仅用 dataset300-v2 train240 的关联困难负例、可靠 wire 负例与忽略区。若端点矢量化仍有限，再试轻量线段端点预测；若 OCR 覆盖仍有限，再试单一 PP-OCRv6 small。|先 smoke、单 GPU 串行。候选参数和预处理必须随完整 bundle 追溯；外部预训练来源不能伪装为本地训练。每次只评一个新增模型方案。|
|P0：组合与发布验证|完成现有外部 OCR 的真实来源导入契约；固定图像、源码、配置、锁与模型 SHA，完整图像重跑、目标容器四任务推理、两次确定性、完整失败清单。|严格 0 ERROR；单图预算和 30–50 图整批预算分别验证；四项分别报告。只有正式符合 bundle/证据要求才通过 model_promotion 生成新锁。|

小编号覆盖和型号分类应依据逐阶段损失安排，不预先假设升级 OCR 一定胜过关联修复。每轮保留单项消融、逐图差异、全部失败/not_run；已有公开 210 图、release50 和反复使用的 val/test 不作为新独立 holdout。

磁盘策略是保留唯一生产锁引用的权重和一套正在验收的必要候选，失败候选保留轻量配置、哈希、日志与指标后淘汰权重；不保存多尺寸、多框架和重复转换版本。当前本轮新增模型为 **0**，IR 快照采用既有 LZX 压缩。

当前四项各 95% 仍未达到。继续开发验证时以指南分项要求为目标，同时清楚区分本地 raw-v1/guide-v1 与官方 evaluator；不将像素 F1、连接对 F1、mAP 或论文总准确率替代四项验收。
