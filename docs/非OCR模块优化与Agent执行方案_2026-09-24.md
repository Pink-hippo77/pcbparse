# 非OCR模块优化与Agent执行方案

日期：2026-09-24。对象：PCB原理图自动解析系统。此文件是下游开发任务规格，本轮仅核查资料并制定方案，没有执行训练、部署或模型晋级。

## 1. 目标与边界

目标是提高图像到 components/pins/nets 的真实正确性及稳定性。沿用 Circuit-IR 和现有 perception → association → graph → nets → validation → output，不从零重构。

本计划排除：OCR检测、识别、文字分组/重排、文字字段分类、文字owner绑定的代码改动。相关输入可以作为下游依赖；遇到缺失文本，记录责任阶段，不在非OCR模块补造。pin到器件几何归属、pin到导线吸附属于本计划。

所有任务遵守当前AGENTS.md。模型锁是唯一生产权威；不得修改blessed/status绕过晋级。GT仅用于独立离线评分或明确标注的oracle诊断，生产与晋级预测保持image-only。缺key/number不能补号或填UNKNOWN。不得用“serializer输出非空”替代准确率。

单agent按依赖推进；本方案不是并行启动多个训练的授权。单GPU训练串行。现有未提交修改必须保留；每次实验写新的work目录；archive与external只读。

## 3. 统一实验与验收协议（N00，P0）

交付：基线清单、当前模型/候选矩阵、数据暴露清单、阶段缓存和独立评估程序。先做5图开发回归，再30张grouped val。release50只作回归/性能，公开210重复集不作新holdout。任何test用于看结果后必须记录暴露，不再次调参并声称独立确认。

每次记录：git HEAD、dirty源码文件清单及逐文件哈希、实际配置与模型权重/类别表/bundle哈希、图片清单及sha256、split来源、设备/框架/provider实际后端、评估器及参数、随机种子。只记录HEAD不足以绑定脏工作区。

缓存分层：模型原始输出→几何恢复→跨tile合并→器件/Pin几何归属→pin-wire吸附→Physical Graph→Electrical Net→验证前IR→裁剪后IR→官方JSON。记录对象稳定ID映射及删除原因，不泄漏至官方JSON。

两种A/B必须分开：
- 模块隔离：固定其他输入的内容哈希，回放当前待改模块。例如评估graph时可缓存所有上游预测。
- image-only E2E：固定OCR权重和代码，但若component变化导致ROI变化，必须重跑受影响的OCR/Pin，不能复用旧ROI缓存制造公平性。

通用度量：一对一匹配；宏/微平均并列；固定全量分母，条件指标另列；缺测null/not_measured；异常与空输出分开。对象主键使用(image_id, object_id)。GT文本/网络覆盖不完整时标记可评范围和排除原因，不将未标注对象自动算错。

每个任务在看候选结果前写gate_config.json。优先沿用既有冻结门禁；新阈值由基线和业务风险确定，不用看到结果后移动门槛。配对报告逐图增益/退化，置信区间按图片重采样，不能把同一图数千个对象当独立样本。

## 4. Component候选落地（N01，P0，依赖N00）

入口：perception/yolo_component_adapter.py、production_provider.py、composite_provider.py；scripts/run_raw_candidate_batch.py、audit_yolo_component_candidate_runtime_smoke.py、package_yolo_component_candidate.py。

步骤：
1. 验证v2权重、类别表、val和paired-test报告哈希。权重候选为 work/yolo/component-yolo11n-v2-precision/weights/best.pt；先验证存在及哈希，不自动使用目录中“最新”文件。
2. 检查YOLO数据配置虽然名为pcbnet-upgrade-v1，其真实源图/派生血缘是否来自许可的dataset300-v2。目录名不能证明合规或不合规；血缘不能确认则禁止训练和晋级。
3. 分三组比较：生产锁基线；仅换component权重且可兼容的公共配置；冻结的v2完整候选策略。区分模型收益与阈值/NMS/边界细化收益。
4. 先验证val组件框指标；再跑image-only下游，报告器件key缺失、Pin位置/归属、网络连接变化与每图耗时。
5. 完成bundle、运行时依赖、导出一致性和晋级证据后进入N11；本任务不直接改主锁。

指标：IoU0.5 P/R/F1、mAP50（不可与F1混写）、各类/尺度/图源分桶、重复检测、tile边界漏检/截断、max_candidates饱和率、Box误报、原始模型召回与合并后召回。

验收：复现已冻结候选策略或解释漂移；按既有门禁判断，不要求立即超过84.1%；下游无无法解释的pin/net退化；生产可加载且保持image-only。

## 5. Component残余错误优化（N02，P1，依赖N01）

只针对错误分桶选择改动：Box内部边缘截断用中心重裁；同tile/跨tile重复分别测NMS；小器件采用受预算约束的高分辨率局部复查；罕见类别检查类别映射和标注后再调阈值。

禁止统一降分数阈值或增加候选上限来刷召回。观察每图128候选上限是否截断真实对象，仅对触顶样本做上限消融，并记录增加的OCR/Pin成本。硬负例只从train挖掘；类别阈值在val选择并冻结。

回归：两个邻近同类器件不能被合并；跨tile同器件需合并；边缘完整框不能被碎片替换。需要训练时走preflight/smoke/串行训练，不优先全量重训。

## 6. Pin检测、几何与器件归属（N03，P1，依赖N00；候选E2E依赖N01）

入口：perception/torch_pin_adapter.py、pin_provider.py、composite_provider.py、training/torch_pin_model.py、association/pin_assignment.py。不改text_pin的文字识别/绑定策略。

先拆两路：GT器件ROI的离线Pin定位诊断；预测器件ROI的真实Pin定位。GT条件仅说明component几何影响，禁止进入正式预测。

核查原图↔ROI↔heatmap的缩放、padding、base/tip、旋转和边方向。输出模型峰值→局部NMS→数量预算→器件归属逐阶段计数。保持已有edge_length_v1，比较预算触顶与漏检，不凭空生成均匀引脚点。

当前edarace为score_threshold=0.75、floor12、pitch8、cap128。0087有143-pin器件的历史标注，若预算约束是同一器件总数，128会构成上限；先核对统计对象和契约，再做128/更高cap的离线消融，不直接设无限大。

指标：定位P/R/F1（主口径沿用raw-v1 5px，2/3/8px仅辅助）、tip/base误差分位数、方向准确率、正确器件归属率、每器件pin-count误差、密集度分桶、重复点与触顶率。编号正确率不是该模块的独立定位指标。

验收：坐标往返≤当前0.5px契约；密集器件漏点改善且重复点/错误归属受控；下游吸附不得通过补造pin提升。

## 7. Wire mask与矢量化（N04，P1，依赖N00）

入口：perception/torch_wire_adapter.py、wire_vectorizer.py；scripts/analyze_wire_mask_components.py、audit_wire_graph_a09.py。

分别测mask和vector，不把pixel F1当连接正确。缓存概率图后对阈值、closing半径、骨架化、RDP简化做单因素消融；比较GT mask矢量化与预测mask矢量化，隔离感知和后处理。

困难样本：细线、斜线、虚线、文字覆盖、器件轮廓、平行线、小间隙、跨tile边界。保留修补坐标、synthetic证据、wire_breaks和修复来源；不能只按修补像素数判断好坏。

指标：mask P/R/F1及容差口径、矢量覆盖/端点偏差、碎片数、伪线段、错误桥接、断网和误并网；阈值降低增加的文字轮廓误检单列。

验收：平行线/跨线负例不误并网，修复收益来自真实断线恢复；相同输入配置输出确定；新修复比例分母明确（像素、segment还是connection），禁止混用。

## 8. Pin到Wire吸附（N05，P1，依赖N03、N04）

入口：association/pin_wire.py、association/geometry.py、graph/physical.py。

对每个pin保存候选segment/physical-group、距离、方向代价、组内折叠、最优/次优差值与决策原因。先判断“没有正确候选”还是“正确候选没选中”，不能将所有unmatched统称no_candidate。

候选搜索可用空间索引加速；容差按线宽和分辨率受控变化，保持硬上限。同一物理wire的多个segment先折叠，避免碎片导致伪歧义。明确tip为电气连接点，base与orientation为辅助，禁止吸附到另一侧平行线。

指标：正确吸附率、错误吸附率、未吸附、歧义；候选可恢复率为独立oracle；新增错误吸附涉及多少错误连接对。扩大半径不是默认优化。

验收：平行线、T形、靠近但不接触、左右反向pin、split segment均有用例；仅在有真实正确连接收益且错误吸附受控时采用新参数。

## 9. Physical Graph与junction判定（N06，P1，依赖N04、N05）

入口：graph/physical.py、union_find.py、wire_vectorizer.py。复用 collect_segment_connections 的证据，不引入无法追溯的直接union。

重点区分：X交叉无连接、带junction dot交叉、T接点、共线断缝、桥接跨线、线端接入。只有许可证据触发连通；不简单按距离扩大合并。

每次union保留rule、节点/线段ID、坐标及证据，支持从错误net回放到第一次错误union。采用rollback或隔离构图试验，不在生产图上做不可逆猜测。确定性junction优先；确有残余错误再评估学习式junction，第五任务启用必须同步配置、锁、bundle和门禁。

指标：连接对P/R/F1、误并/误拆数量、完整物理net成员正确率、junction局部混淆、组件数、修复贡献。连接对容易被大net支配，同时报告按net/按图宏平均。

验收：负例不误并网；通过加入许多伪边得到的召回不予接受。端点合并、共线合并、gap repair分别开关消融。

## 10. Electrical Net与标签作用域（N07，P1，依赖N06）

入口：nets/hypergraph.py、nets/__init__.py、IR NetLabel。标签文本及其绑定由冻结OCR提供，本任务仅消费结果。

核查当前按(net_type,resolved_text)分组的作用域：当前支持单图时保持图内语义；若输入含多页/分区，先明确契约再引入page/scope字段，不能自行把所有同名标签跨图合并。

分别测试signal/power/ground开关。维护默认保守行为；当前edarace只开启signal合并，power/ground关闭。库或常识不能把低可信标签强行接到电源网络。

指标：电气连接对P/R/F1、完整net准确率、标签触发的union次数及正确率、同名异作用域误并、net成员丢失。对无文字证据导致的未合并标upstream_missing，不改OCR或补造标签。

验收：同scope同名、不同scope同名、未绑定标签、空标签、重复标签、电源地策略都有确定性测试；最终net引用全部可解析。

## 11. Validator、裁剪与输出（N08，P0，依赖N00；全链验收依赖N07）

入口：validation/*、output/official_schema.py、official_serializer.py、pipeline/orchestrator.py、submission_agent.py。

审计strict/degraded全部入口。缺component key/pin number禁止补号、UNKNOWN或重命名掩盖；选择降级裁剪时必须重算受影响net、验证引用和连接语义。记录每个删除对象及reason，区分原本空图、裁剪至空、异常fallback、写入失败。

不把IRState.VALIDATED字样当作实际0 ERROR证明；检查所有官方输出路径都经过有效Validator门禁。批次局部失败写error_manifest，不能丢失其余成功图。

指标：schema通过率、真实非空率、缺身份裁剪数、悬空引用、nets_dropped/nets_affected、失败类别。schema通过仅是结构指标。

验收：输入IR不被serializer静默改写；官方顶层仅components/pins/nets；相同图/配置至少3次字节级一致；坏图、空图、磁盘写失败和timeout可追溯。严格输出不接受任何伪造身份。

## 12. 性能、可观测性与部署（N09，P1；N11发布前置）

入口：pipeline/context.py、production_provider.py、service/readiness.py、cli.py、submission_agent.py、docker/、requirements.edarace.txt。

优化顺序：阶段profiling→消除重复加载/变换→内容缓存与空间索引→真实批处理→必要的导出/精度优化。缓存键包含图像/ROI像素、坐标变换、权重、配置及预处理版本，不能复用错误ROI。Oracle不得进入缓存生产命名空间。

度量冷启动/热运行、各阶段耗时、单图最大值、全批总时长、P50/P95、失败率、CPU内存/显存峰值。5图不能作为可信P95证据；固定回归套件可用于性能但非独立准确率泛化。单图≤600秒，全批≤实际配置上限（baseline7200、edarace7000）；不能把两个分离实验耗时相加当替换后的生产整图。

ONNX当前CUDA缺DLL会回退CPU：记录session实际provider，不仅看torch.cuda.is_available。修复只能在匹配官方镜像CUDA/PyTorch约束的环境中验证，不为了本地运行盲目升级全部框架。

部署验证：在项目docker中构建，不改external官方资产；检查路径、编码、只读模型、断网/离线权重、坏输入、批量重启。healthcheck进程活跃与require-ready分开；不能以测试环境可import替代官方容器可执行。

## 13. 数据底座、难例与器件库（N10，P2，依赖N00）

数据：继承dataset300-v2 240/30/30 grouped split；所有tile/ROI/crop/增强跟随源图。训练前检查标注类别、pin所属器件、tip/base和wire连接契约，GT异常不静默修到预测中。新难例来自train；val只用于选择，test不反复调参。所有修标记录前后差异及来源。

器件库：knowledge/library_index.py、library_matcher.py已有基础，先测覆盖与检索精度；本任务只评估兼容类别、可见pin数/方向一致性及解释，不改OCR候选。冲突时保持不确定，不能为匹配库而添加坐标、隐藏pin或编号。无检索来源/许可证则不晋级库资产。

## 14. 晋级与交付（N11，依赖N01/N08/N09及所有拟发布任务）

先完成candidate bundle、完整血缘、导出一致性、image-only E2E、确定性与运行预算证据。data_tools.model_promotion是唯一写新生产锁的途径；先使用工具的审计/报告能力，再决定promote。不得手工改blessed/status，也不得凭本计划自动宣称release_ready。

区分 implemented / fixture_passed / development_e2e / release_ready。官方evaluator缺失仍单列，不把raw-v1或guide-v1写成官方成绩。回滚保留旧权重、旧锁、旧配置及复现命令，不覆盖旧证据。

每项交付需包含：修改文件与原因、前后指标（相同分母）、失败样例、配对退化、测试命令及退出码、输入/源码/模型/配置哈希、sidecar_access、split_role、oracle标记、运行设备、风险及下一依赖。

## 15. 推荐实施顺序

第一轮：N00基线 → N01接入v2候选影子评估 → N08门禁审计；优先兑现已有器件检测成果。

第二轮：N03 Pin几何与N04 wire各自定位 → N05吸附 → N06物理图 → N07电气net。先定位错误阶段再改变模型。

第三轮：N02残余检测优化、N09预算与Docker、必要的N10难例/库 → N11候选晋级。任何训练只在已证实感知瓶颈后执行。
