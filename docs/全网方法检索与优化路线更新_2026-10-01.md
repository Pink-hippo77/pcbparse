# 全网方法检索与优化路线更新

检索与核对日期：2026-10-01。对象为本工作区的 PCB 原理图解析系统。检索覆盖近期论文、作者仓库、官方模型发布和赛题公开入口；技术结论采用原始论文、作者代码及官方文档。以下是方法筛选和待验证方案，不能视为已经测得的系统增益。

**存在比继续调整局部距离阈值更值得试验的方法。优先组合是：可见文字与器件库共同约束身份，文字/符号/导线分离，骨架端点辅助引脚定位，以及按交叉类型构建物理连接。PP-OCRv6 small 是新的轻量 OCR 候选。现有 Circuit-IR 主干继续使用。**

没有查到在本赛题同一 JSON 契约下，证明器件、引脚、网络、线段四项分别达到 95% 的可直接替换方案。论文的 mAP、坐标匹配 F1、拓扑同构、NED 和 Pass@5 与赛题四项指标不同。全部外部方法在本系统中均尚待对照验证。

## 应采用的具体改进

下面的工作包是基于外部方法和本地失败证据提出的实现假设。优先级表示试验顺序，不表示已经证明的收益。

**1. 联合身份匹配，继续使用现有全局求解器。** 当前 `association/pin_assignment.py` 已有 Hungarian 和有序动态规划；`knowledge/library_matcher.py` 已有带 UNKNOWN 的器件库检索。新工作应连接文字字段候选、整侧文字行、可见编号/名称、器件型号候选和方向证据，让它们在同一器件内一致评分；保留拒绝和次优差距。不能仅用距离把 OCR 数字赋给最近 pin，不能把库中的全部引脚当作图中已存在引脚。

重点先修 IC 型号：当前候选型号仅 3/78，器件库无法在没有身份依据时可靠约束编号。型号字符原文、候选及来源分别保留，绝不为了找到库项静默改写字符串。对可见 pin，只有唯一、可追溯的匹配才能提供已有字段候选；仍不生成 key、不可见 pin 或坐标。

验收观察已有文字的分类正确率、owner 正确率、编号/名称联合正确数，以及最终被裁去的器件/引脚。编号和名称分开消融，再测联合方案。第五轮编号行惩罚和局部配对曾造成回退，作为固定回归案例。仅提升中间分数或名称数量不构成采用依据。

**2. 先分离文字和器件笔画，再尝试骨架引脚候选。** 保留原图用于 OCR 和全部图像证据，另建仅供图构建的线条视图。根据预测 OCR 四边形与真实墨迹识别文字笔画；根据可见闭合边框识别符号轮廓；保留垂直于器件边缘的引脚短线和通往端点的真实线条。文字与线条重叠时保留不确定性，不能将整个文字矩形或整个器件框直接清空。

借鉴 SINA 的候选生成思路，使用去文字后的骨架端点、器件周边穿出方向和原有 Pin 热图共同提出候选。它是新增候选来源，不立即替换当前 Pin 模型。引脚 tip 必须来自图像中的连接点，不能将框边界当 tip，也不能为接网把点任意移动。先验证 5px 范围定位、owner 和最终身份保留率，再判断是否纳入正式分支。

第二轮整框过滤曾降低错误连接，却丢掉正确连接，不能重启同一方案。小矩形也可能属于图注或分组区域；分类、闭合形状及穿出线证据不足时不删。

**3. 用带类型的连接候选限制误并，逐项加入交叉和缺口证据。** 当前已有 Physical Graph、交叉规则和共线合并。新增的是明确区分 pin tip、线段端点、T 接点、带点交叉、平面交叉、跨线桥和符号边框；每一条吸附、缺口修复及合并记录图像依据和分数。局部容差随线宽/字号变化，但仍在原图坐标测量官方位置误差。

先只抑制已有错误桥接，再测试有证据的缺口恢复。缺口两侧须方向一致、附近无平行线竞争，并有原图或概率图支持；距离近不是充分证据。不能因端点度数不足补一条不存在的线，也不能把同器件两 pin 必然视为非法连接。交叉类型结合绘图风格，避免把“有交叉就连接”或“无圆点都不连接”作为全图规则。

全局标签与物理连通分开核对。相同、明确、唯一绑定的网络标签才允许逻辑合并；AGND、DGND、PGND 不因都属 GROUND 自动合并。同步记录最终网成员和网络内线段分段，避免像素改善后 JSON 网络/线段仍错误。

**4. PP-OCRv6 small 做单一、可淘汰对照。** 官方 ONNX [det 文件](https://huggingface.co/PaddlePaddle/PP-OCRv6_small_det_onnx/tree/main)约 9.88 MB，[rec 文件](https://huggingface.co/PaddlePaddle/PP-OCRv6_small_rec_onnx/tree/main)约 21.2 MB，另有字典和配置。体积适合作为 4GB 设备上的优先验证对象，实际峰值内存和耗时仍需实测。

它不能直接复用当前英文识别器的字典、均值/方差和输出维度假设。正式试验前锁定发布 revision、SHA256、许可、词表、图像归一化、CTC 解码及算子，并验证目标容器 ONNX Runtime。先固定同一批原图，对照检测覆盖、crop exact 和最终字段；再跑完整多级图像流水线。只保留生产权重及一套正在评测的候选，失败立即淘汰权重、保留轻量证据，避免保存三个尺寸、多种框架和重复转换版本。

现有未晋级的 ONNX OCR 整批图像验收及真实来源契约仍须完成。外部预训练模型不能伪装成 dataset300-v2 训练产物；不能为导入它放宽哈希、lineage 或晋级门禁。

**5. 需要再训练时，先改监督和负样本，后考虑新网络。** 仅使用 dataset300-v2 的 train240；同源增强跟随父图分组。用真实 wire 标注和可靠忽略区明确文字笔画、器件边框及近邻平行线负样本，保护引脚出口。不完整标注不强行设负类。检查现有 soft-clDice 的贡献；继续以最终误并/断网和线段端点评价选模型。

如果端点规则仍有明确上限，再做 Netlistify 思路的轻量端点/连接候选评分对照；不要一次引入检测、方向、DETR、VLM 多个新模型。4GB GPU 串行训练、先 smoke；只保留必要 best 和 resume，不保存每 epoch 的大权重。

## 实验及采用门槛

|步骤|产物与证据|采用条件|
|---|---|---|
|每个工作包单独开发|现有冻结感知回放、逐阶段损失、每图差异、失败案例|只有预期字段/连接改善才进入图像试验；实质回退先修复或淘汰|
|身份与拓扑组合|同一组完整原图，仅图像推理；GT 只在离线 scorer 使用|同时报告裁剪前和最终 IR，包含所有失败/not_run，拒绝缺 key/number 的伪填充|
|候选生产验收|真实完整 bundle、配置/源码/权重/输入哈希、目标 Docker、两次字节确定性、适当回归|Validator 0 ERROR，整批低于 7200s，覆盖全部目标图；只经 model_promotion 更新锁|
|95% 目标核验|ComponentF1、PinF1、NetHypergraphF1、NetLineF1 各项正式口径报告|四项分别≥0.95；官方 evaluator 未获得时只标为按指南开发验证，不宣称官方达标|

50 图比赛的硬限平均为 144s/图，30 图为 240s/图；还须预留加载和调度时间。单图低于 600s、CPU fallback smoke 或外部 A100 速度，均不能证明整批/GPU P95 达标。现有 0165 的 213.61s 含加载且有并行 CPU 负载，只作执行证据。

本次完成检索、源码对照和路线更新；没有运行外部模型、没有复制/下载权重、没有训练、没有新增生产变更。当前生产配置仍为 `pin_name_row_penalty=0.22`，body-name context 在生产关闭；第五轮实际执行通过的 unittest 为 777 项、跳过 71 项，本次未重跑这些测试。主锁和生产配置 SHA256 由附带绑定文件核验。既往删除的 193 个多余模型约 7.34 GB 不恢复。

执行顺序为：联合身份与型号候选 → 文字/轮廓分离及骨架候选 → 交叉/缺口/标签逐项消融 → 必要时单一 PP-OCRv6 small 对照 → 完整图像和容器验收 → 正式四项评价。优先方法已选定；是否采用以本系统可重复的最终输出增益为准。
