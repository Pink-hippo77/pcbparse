## 统一训练纪律

### 数据与 split

- 只使用 `dataset300-v2` 与绑定的 240/30/30 grouped split。
- 训练前验证 600/600 源文件哈希、300 样本、147,758 条五任务记录和零 duplicate-group leakage。
- val 用于模型、阈值和后处理选择；test 只做最终诊断/评估，不参与选择。
- 任何标注、物化配置或筛选变化都生成新的内容寻址版本，不覆盖旧 lineage。

### 指标

- Component：mAP50 为主门禁，同时报告 class-aware 微平均 P/R/F1、按类/尺寸/域召回。
- OCR：recognizer exact/CER 与 detector P/R/Hmean 分开；增加 OOV、overlength 和 eligible coverage。
- Pin：使用一对一 4px 匹配的 TP/FP/FN、微平均 P/R/F1、pred/GT；`pck_4px` 明确标为 recall alias。
- Wire：skeleton/centerline P/R/F1、connectivity、component-count error；同时检查 raw-v1 Graph。
- Junction：真实六类 per-class P/R/F1/support 与 macro-F1；zero-support 类不能被 observed-only 指标隐藏。
- 所有任务：导出/原生推理最大误差、样本数、设备、精度、峰值显存和耗时。

### 续训与配置哈希

正式续训必须恢复 current/best model、optimizer、GradScaler、early-stop history、Python/NumPy/Torch/CUDA RNG 与 DataLoader generators。当前实现按绝对 epoch 计算余弦学习率，恢复后不会重放第 1 轮调度。

2026-08-23 的 Pin v4 曾因训练配置模型新增三个字段而在 resume 时 fail-closed。当前只在下列新增字段全部保持精确默认值时接受旧 hash：

- `component_balanced_sampling_power = 0`
- `component_balanced_sampling_max_weight = 8`
- `ocr_target_shrink_ratio = 0`

这只是对语义无变化配置的严格兼容，不允许真实超参数漂移。任何非默认值变化都必须新开 output 目录或使用与 checkpoint 完全一致的配置。

## Component：修复长尾与小目标召回

### 已证明的问题

- v3 冻结 val 有 1,112 个 GT，只匹配 260 个；召回 `0.2338`。
- 全部存储分数扫描的最佳微平均 F1 仅从 `0.2856` 提高到 `0.3018`，同时召回下降到 `0.2212`。
- 0024 test 的 512 Tile 在现行阈值命中 16 个 Box，但 C/Gnd/R 共 11 个全漏。Tile 带来局部召回，不代表长尾类已解决。

### v4 方案

配置：`configs/train/dataset300_v2_component_v4.json`

- 从 v3 checkpoint SHA-256 `fc9bbf8…5804e` 热启动；
- 768×768，12 epoch，LR `5e-5`，max detections 300；
- WeightedRandomSampler：样本权重由其最稀有可用类的逆频率决定，power `0.25`、cap `4.0`；
- 验证与 checkpoint generator 均保持可复现；
- 门禁保持 `bbox_map50 >= 0.25`，不因现有候选失败而放宽。

验收：

1. mAP50 通过；
2. 微平均 F1 高于 v3 `0.3018`；
3. R/C/Gnd/Box 等类别与 small/medium/large 召回不出现关键回退；
4. native/导出一致；
5. 形成 model card + bundle manifest；
6. 严格 E2E 的 key、Pin owner 和 Graph 指标不退化。

## Pin：从召回式 PCK 改为完整检测质量

### 已证明的问题

旧 formal status 只用 `pck_4px >= 0.5` 放行。原始 decoder 产生 14,064 predictions / 2,640 GT；后续 component-box 边界先验把预测压到 3,224，且保持 1,370 matches。现行完整口径为：

- precision `0.42494`
- recall/PCK `0.51894`
- F1 `0.46726`
- pred/GT `1.22121`

该结果证明 box 边界先验有效，也证明旧 bundle 的单指标门禁不完整。锁文件已记录 384×384、stride 4、score 0.15、NMS 2、max 128、box margin 4，但旧 model card/bundle 没有绑定这一整套策略，因此不能 promotion。

### v4 方案

配置：`configs/train/dataset300_v2_pin_v4.json`

- 384×384、base channels 16、weighted BCE、30 epoch；
- score `0.15`、heatmap NMS `2`、每元件最多 128、box margin `4px`；
- 训练数据 Component ROI 的 margin 为 64px；生产 Pin ROI 已与 OCR ROI 解耦，可独立使用 64px；
- 当前已恢复并完成 epoch 7，最新 P/R/F1 为 `0.3500/0.4439/0.3914`；最佳 recall 仍在 epoch 6，且两轮都低于旧 checkpoint。

终态选择规则：

1. 同一冻结 val、同一 decoder 计算微平均指标；
2. PCK/recall `>=0.5` 且 pred/GT 在 `[1,2]`；
3. F1 必须高于旧候选 `0.46726`，否则保留旧权重并对其重新打包；
4. 导出一致性、固定 decoder、predictions、metrics、model card、bundle manifest 必须绑定同一 checkpoint SHA；
5. production ComponentView 与训练 ROI 变换做全量一致性检查。

## OCR：识别器通过不代表设计符链路通过

### 已证明的问题

v2c recognizer exact `0.6785`，但 detector recall 只有 `0.3250`。在 0024 密集 4×4 Box 场景：

- 扩大 Component ROI 到 64px 仍无法得到 K0–K15 的可用识别；
- 甚至对精确 GT crop，当前 recognizer 的 K 字符串 exact 仍为 0/16；
- 共享大 ROI 会产生重叠 owner 和邻框文本污染；
- OCR/Pin ROI 解耦能减少重复 token 和延迟，但不能单独恢复设计符。

### 修复方向

- detector 正样本 mask 允许向内收缩，但 GT box 保持完整，减轻相邻文本正区粘连；
- 映射回源图后不足 1 个源像素支持的 detector box 在 padding 前拒绝；
- OCR Component ROI 使用独立 view ID 与 padding，避免和 Pin 证据/owner 混淆；
- Box 设计符关联接受任何合法 designator 前缀，但不硬编码 K，也不生成内部 `C_*` key；
- 下一次训练门禁增加 detector Hmean/recall、设计符 subset exact/coverage 和严格 E2E key coverage。

任何“自动填 K0–K15”“用内部 C_1…C_16 代替视觉 designator”都会造成测试泄漏或官方字段伪造，禁止采用。

## Wire 与 Graph：停止只优化 pixel F1

formal4 的 skeleton F1 已为 `0.8560`，但 baseline 0024 的 raw-v1 wire F1 `0.8010`、Graph pairwise F1 `0`，并有 24 个 disconnected-net ERROR。下一阶段优先：

1. 用 GT Wire + predicted Junction、predicted Wire + GT Junction、GT Pin + predicted Graph 做 oracle 拆解；
2. 检查 vectorize 后 segment 数、短段/重复段、junction 候选数和 net split/merge；
3. 在冻结 val 扫描 gap repair、endpoint merge、pin snap、crossing threshold；
4. 对 Component 512 / Wire 1024 域分离做分层验证，不再共享 Tile 策略；
5. 只有 Graph 指标与严格错误同步改善时才替换 Wire/Junction/Graph 参数。

## Junction：真实标注是不可绕过的门槛

现有真实 val support：endpoint 3027、bend 443、T 28；connected cross、non-connected cross、noise 均为 0。2,283 条 UNKNOWN cross 记录形成 1,119 个物理候选簇；自动证据审计可以给 review proposal，但 accepted-as-ground-truth 仍为 0。

执行顺序：

1. 使用 `tools/junction_labeler.py` 人工裁决并保留 reviewer、时间、理由与原始证据；
2. 对 train/val/test 保持严格分工，test 不进入训练；
3. 将签署后的 review override 重物化到新的内容寻址 run；
4. 检查六类真实 support、重复/同源泄漏与 hardcase 分布；
5. synthetic 只作为 train augmentation，真实 val 不混 synthetic；
6. 重训并要求六类 macro-F1 `>=0.65`；
7. promotion 时提交正式 human-review evidence。

不得把门禁改为 `macro_f1_observed` 来规避零 support。

## 当前执行与复现

```powershell
$env:PYTHONPATH=(Resolve-Path '.\src').Path
$python=(Resolve-Path '.\.venv-train\Scripts\python.exe').Path

# 数据 preflight
& $python -m pcbparse.training.preflight_cli `
  --config .\configs\train\dataset300_v2_pin_v4.json `
  --workspace-root .

# Pin v4：同一 output 自动识别兼容 checkpoint
& $python -m pcbparse.training.torch_train_cli `
  --config .\configs\train\dataset300_v2_pin_v4.json `
  --task pin --output .\work\train-pin-v4 `
  --workspace-root . --device cuda --precision fp16

# Pin 出现终态证据后，Component v4
& $python -m pcbparse.training.torch_train_cli `
  --config .\configs\train\dataset300_v2_component_v4.json `
  --task component --output .\work\train-component-v4 `
  --workspace-root . --device cuda --precision fp16

# 全量测试与 readiness
& .\scripts\run_tests.ps1 -Python $python
& $python -m pcbparse.cli healthcheck --require-ready
```

训练日志中的 `status=running`、单个 epoch 指标或 `gate_failed` 都不会自动修改 `models.lock.json`。只有完整 bundle 和五任务 promotion 工具能生成新锁。

## Promotion 验收清单

- [ ] 数据、split、task manifest 哈希全部一致；
- [ ] 五任务各有 exactly one verified candidate bundle；
- [ ] Component mAP50 与分层召回通过；
- [ ] OCR recognition + detection + coverage 通过；
- [ ] Pin 微平均 P/R/F1、pred/GT 与 decoder 绑定；
- [ ] Wire 指标通过且 Graph 不退化；
- [ ] Junction 真实六类指标与 human-review evidence 通过；
- [ ] 固定 image-only 严格套件 0 ERROR、Serializer 全通过；
- [ ] production adapter load 与 fixture smoke 通过；
- [ ] 目标 Docker/GPU 的 30–50 例演练通过；
- [ ] 官方 sample submission/evaluator 已冻结。

只要其中一项缺失，模型可继续作为诊断 candidate，但不可 bless。
