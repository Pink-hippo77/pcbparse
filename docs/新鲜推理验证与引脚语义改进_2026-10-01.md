## 新鲜原图入口发现的问题

第八轮使用主锁中的 component/pin/wire 加既有未晋级 DB/CTC OCR，重新运行 exposed grouped val30 原图。OFF 对照使用同一轮刚产生的感知 IR，验证身份原型的下游作用；它不重复模型推理。原图推理不读取 GT，GT 仅在离线 scorer 使用。

首次全批耗时 1,833.891s，**29 图完成，0234 图失败**。该图一个 float32 检测概率为 `1.0000001192092896`。修复将容差限定为绝对 `float32 epsilon`（约 1.19e-7），只把这一数值范围内的端点舍入误差归一到 [0,1]；实质越界、NaN 和 Inf 仍报错。原失败记录和 `error_manifest.json` 保留。

相关 17 项 OCR 测试通过。0234 图修复后四模型重跑完成；Python 文件审计钩子只允许 Dataset300 内的指定原图，未发现被拒绝的 sidecar 打开尝试。该钩子覆盖 Python 审计事件，不是操作系统或原生库沙箱。

修复版完整 30 图复跑已完成：候选及 OFF 控制各 30 图成功，含控制和快照压缩共 **2,380.641s**，代码与输入绑定未漂移。两分支共 60 份 JSON 均与参考结果逐字节相同，其中 29 图参考首次成功批次，0234 参考明确区分的修复版单图。Python 文件钩子覆盖 30 张白名单原图。局部 ONNX CPU fallback 时延不能作为 GPU P95 或官方 Docker 全批证据。

## 第九轮器件裁剪文字对照

隔离原型只允许既有编号—名称—pin 点上下文处理 component ROI，继续排除 side_strip。仍保护已有权威字段、标准位号和长型号；只改变已有文字的角色分类，不生成编号、名称原文、位号、坐标或不可见 pin，也不直接给 OCR 写 owner。规则沿用实际可见同行编号、pin 方向、器件半侧与距离约束，最终由现有全局匹配器判断归属。

21 项测试通过，其中包含原有控制用例与器件裁剪边界用例。7 图试验正确引脚名增加 36；完整 30 图回放增加 **58**。回放感知来自第八轮 29 个原图结果及明确记录的 0234 修复结果；它不构成第二次完整原图模型运行。

## 严格图验证还未通过

使用各分支实际绑定的图阈值重新运行 Schema/Reference/Geometry/Graph Validator，**20/30 图、352 个 Physical Net 报 `NET.DISCONNECTED_SEGMENTS`**。同样的问题存在于修复版原图候选、OFF 控制和器件裁剪原型中，共 90 份输出复核的 60 份未通过严格图验证。当前 degraded 模式把该错误转为 WARNING，因此已有快照中“0 ERROR”不证明严格验证通过；这些输出只保留为开发诊断，不晋级。

独立诊断检查了已接受 pin_snap/直接接触的几何连接路径，未解释任何一个断连网络，排除“补上 pin 路径即可解决全部问题”的简单假设。接下来核对建图、去重修复、连接证据和验证器之间的差异，必须修复真实一致性问题，不能扩大容差或信任未经几何核验的 metadata 来消除错误。

Docker 服务已恢复；现有官方基础镜像实测 PyTorch 2.5.1+cu121，基础镜像缺 Pydantic/ORT。既有适配镜像含 Pydantic 2.13.4、ONNX Runtime GPU 1.21.1，CUDA 可用。当前工作区主锁与配置在适配镜像中的 `healthcheck --require-ready` 通过。该 smoke 的感知结果为 0 器件/0 引脚/0 线段，仅证明加载与固定 smoke 运行，不能替代原图质量、候选 OCR 会话、GPU P95 或完整提交验证。

## 继续实施与验收

1. 先修复 Physical Graph 与严格 Validator 的一致性，明确阻止生产通过降级掩盖真实断连错误。之后把器件裁剪上下文做成默认关闭的明确配置项，核验新的完整原图入口。冻结回放收益不能替代原图验证。
2. 对编号分类、编号/名称同行关系和 pin owner 分别消融；使用现有 Hungarian/有序 DP 的唯一性与次优差距，不以最近距离或库顺序硬填编号。
3. 用原图墨迹和骨架提出可见 pin 候选，保留真实出口短线；再逐项改善交叉类型、平行线竞争、缺口与网络标签。当前几何召回和最终网络仍有较大缺口。
4. 为外部预训练 OCR 区分真实源模型训练来源与本地评估 lineage。当前训练产物 schema v1 不能把它如实描述为 dataset300-v2 训练模型，禁止填造训练哈希或手改模型锁。目标 Docker/ORT、完整 bundle 和晋级门禁通过后再选择生产模型。
5. 按指南同时检查 ComponentF1、PinF1、NetHypergraphF1、NetLineF1，各项均 ≥0.95。raw-v1 的字段计数、几何、连接对与像素 F1 都不是这四项正式成绩；保持官方指标为空。val30/release50 已暴露，只作开发回归。

本轮未下载、训练或复制新权重。仅引用必要的生产四模型及既有 OCR 候选，快照采用 LZX 压缩。生产配置和模型锁保持原哈希，源码只修复了候选 OCR 的数值边界；第九轮语义变化仍在 `work/` 中。
