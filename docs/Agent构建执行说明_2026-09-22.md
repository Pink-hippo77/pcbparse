## 接口实现建议

下面的协议是设计草案，用来先明确模块责任。实施时优先复用现有 Pydantic 模型，而不是同时保留两套重复实体。

```python
class ContractAuditor:
    def compare(self, targets, profile, guide_rules) -> ContractDiff: ...

class LibraryMatcher:
    def retrieve(self, observed_fields, observed_pins, top_k=5) -> list[LibraryCandidate]: ...

class EvidenceViewBuilder:
    def build(self, image, ir, ambiguity_task) -> EvidenceView: ...

class DecisionVerifier:
    def verify(self, task, decision, ir) -> VerifiedDecision: ...

class ErrorCaseExporter:
    def export(self, ir_before, ir_after, diagnostics, lineage) -> ReviewBundle: ...
```

EvidenceView 至少包含原图 SHA、ROI bbox、local_to_global、raw_crop、numbered_crop、id_map 和 evidence_ids。LibraryCandidate 至少包含 model_name、library_version、候选 pin number/name 集、匹配依据与不一致项。VerifiedDecision 必须记录是否实际应用、拒绝原因和需要重建的对象集合。

## 如授权并行构建

先由集成负责人完成 A00–A03 并冻结接口。之后可分为数据/标注、OCR/器件库、Wire/Graph 三个边界清晰的工作面；检测/Pin 由有 GPU 的任务按队列运行。共享文件 `ir/models.py`、`pipeline/orchestrator.py`、`output/official_schema.py` 只由集成负责人合并，避免多个 agent 同时改同一契约。该安排是未来可选建议，本次没有启动子 agent。

## 停止或回退条件

- 功能依赖未知官方契约：保留版本化接口与差异报告，不擅自把争议标注改成确定真值。
- 检测上升但 pin/net 下跌：保留候选，暂停晋级，分析框、owner 与字段绑定变化。
- 修复断线引发误并网：恢复旧规则，新增该局部负例，重新评估。
- 模型只提高非空率却增加错误 key：拒绝该候选，检查匹配和拒绝机制。
- 远程推理不带图像或服务不可用：UNKNOWN 回退，保留预算与失败日志。
- 无独立 holdout：可以继续开发回归，不得报告独立泛化结果。

最终交付应明确说明完成的是哪些代码模块、哪些真实验证、哪些仍待数据或平台确认，不用“整体完成度 90%”代替可复核的结果。
