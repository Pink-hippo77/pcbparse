# 全模块优化执行方案（2026-10-03）

建议将下一轮主线定为：**先恢复有图像依据的器件/引脚身份，再提高几何与拓扑质量，同时将已经验证的性能优化纳入可复现候选。** 保留 Circuit-IR 和现有分层架构，每个模块都有独立任务、对照实验和退出条件；不以增加参数量或输出数量代替端到端进步。

本方案依据本次本地源码、模型锁、配置检查，以及截至 2026-10-03 的服务器报告副本，并重新检索原论文和官方工程文档。**本次没有连接服务器核验原始 cycle74/79 产物，没有重新训练或运行完整推理。** 服务器数字属于已记录的开发实验结果；生产状态以本地权威锁为准。计划指标是拟定验收目标，不是收益预测，也不是已完成事项。

**3. 检索方法如何落到本项目**

| 外部原始来源 | 值得借鉴的方法 | 本项目采用方式与限制 |
|---|---|---|
| [PCBnet 原论文](https://arxiv.org/html/2608.27923v1) | 局部文字定位、类别前缀、几何对齐和局部唯一性 | 用于候选约束和局部重识别；不照搬生成式补字；论文 OCR/连接指标不可映射成竞赛成绩 |
| [SINA 原论文](https://arxiv.org/html/2607.01609v1) | 文字掩膜后的骨架端点与器件框交会，交叉线专门处理 | 将几何 pin 提议作为热图的补充；电气交叉保留独立通道；禁止由框形状凭空生成 pin 编号 |
| [Image2Net 原论文](https://arxiv.org/abs/2508.13157)及[官方材料](https://github.com/LAD021/ci2n_datasets) | 方向/镜像、交叉点分类和网表编辑距离诊断 | 借鉴错误类型与测试设计；外部数据不进入当前训练，NED 不替代 raw-v1/指南回归 |
| [clDice 原论文](https://arxiv.org/abs/2003.07311) | 用骨架约束线状结构连通 | 项目已实现；消融现有权重即可。二维像素连通不等于电气连通，clDice 不能解决无连接交叉语义 |
| [PARSeq 原论文](https://arxiv.org/abs/2207.06966)及[作者实现](https://github.com/baudm/parseq) | 专门的图像文字识别与上下文解码 | 仅作 P2 的 IC 型号/长引脚名裁剪对照；当前先复用 medium OCR，不默认下载或替换整套 OCR |
| [置信校准原论文](https://proceedings.mlr.press/v70/guo17a.html) | 温度缩放等后校准 | 区分字符、角色和 owner 概率；仅在训练内部 grouped 校准子集拟合。校准本身不会纠正错误的类别排序 |
| [Ultralytics 分片推理文档](https://docs.ultralytics.com/guides/sahi-tiled-inference) | 高分辨率切片和重叠合并 | 针对小器件、边界截断做增量消融，记录重复框和时延；不照抄示例窗口 |
| [ORT profiling](https://onnxruntime.ai/docs/performance/tune-performance/profiling-tools.html)、[I/O Binding](https://onnxruntime.ai/docs/performance/tune-performance/iobinding.html)、[CUDA EP](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html) | 算子画像、减少设备复制、固定形状/地址的 CUDA Graph | 先画像，再缩减 OCR 输出和分桶；按服务器已装版本核验支持。Provider 列表出现 CUDA 不证明所有算子在 GPU |

下面的优先级、联合目标、恢复收益调度和实验门槛是针对本项目的设计建议，尚未验证收益。

**4. 数据与评估：给所有模块一个可信的增量基线（T00、T01）**

第一步封存两条基线：Bprod 为当前生产锁与实际生产配置；Bdev 为核验后的 cycle79 开发候选。固定 input manifest、代码含未提交修改的哈希、模型/配置/静态库哈希、evaluator 版本和运行环境。任何借用旧输出的实验必须验证依赖哈希，不能只看文件名或 cycle 编号。

按 Circuit-IR 的稳定 internal_id 输出阶段留存账本：感知→关联→裁剪前→裁剪后→图→官方 JSON。删除原因采用互斥主因并保留附加原因；例如父器件缺 key 与 pin 自身缺号不能重复计入总损失。对 OCR 拆开统计：可见字段覆盖、正确原文进入候选池、角色正确、owner 正确、最终被保留。只有这样才知道下一次应补检测、重识别还是改绑定。

为网络同时报告：两端可用的真实连接对比例 S、在两端可用子集上的连接召回 C、全量连接召回。用 S×C 解释该连接对定义下的损失；不把这一分解推广为 hypergraph 得分公式。另列错并网、断网、错 pin snap、标签误并、线段归属和端点误差。

数据仅来自 dataset300-v2。训练内部按原 group 划出小型 calibration 分区，不能将同图裁剪分到拟合与校准两侧。对已接触 test/val/release50 的历史保留暴露记录。公开 210 张不可充当新 holdout。新增独立评测集是待补证据项，不以重新划分旧集解决。

建立训练图困难区域队列：小字、型号/位号混淆、拥挤 pin、文字压线、无点交叉、密集 junction。人工审查优先看“会影响最多真实可见对象”的区域；审核结果进入训练分区标注修订/掩码清单，不能回填开发预测。每轮先审查约 100 个区域是工作量建议，数量可以按实际误差分布调整。

验收：每图阶段账本可闭合；每条指标包含 TP/FP/FN 或正确数/eligible/masked；按图或原设计 group 做配对 bootstrap，不能将同图数千像素/字符视为独立样本；开发区间不能证明独立泛化。

**5. OCR 与 association：最高优先级恢复身份（T02–T04）**

先复核服务器 `0030: R3→LM334`、`0038: U5→PCF8563` 两个例子：打开真实 crop、原文、role 分数、owner 候选、拒绝原因与最终 key，区别“读取错误”与“文字读对但角色错”。本地 helper 已证明型号字符串可通过正则，但服务器私有 `pair_features.valid_role` 本次未直接读取，迁移前必须核对。

T02 在现有候选池上加入跨角色竞争。候选定义为 `(observation, role, owner)`，role 至少含 designator/model/value/pin_number/pin_name/net_label/unknown。重叠的 global/ROI/scale2 观测按图像位置及来源聚类，避免同一份文字因识别多次获得多票；位置不同但字符串相同的文字保留独立观测。

约束优先基于视觉：一个观测不能同时被当成器件型号和另一个对象的位号；每个字段的容量按真实输出契约定义；pin 侧边顺序复用现有 DP；owner 的硬约束只对来源可靠的已核验 owner 使用，不能让早期错误关联永久锁死。类别前缀以版本化兼容表为先验，合法例外保留；不使用 `LM334` 字符串黑名单，不把所有 IC 强制改写成 U 前缀。重复可见位号和多单元器件遵循现有契约，不能实施无条件全图字符串唯一。

使用一个显式 unknown/拒绝选择，与距离、侧边、行列一致性、角色冲突和 owner 分数一起决定分配。先落地可解释约束与已有轻量模型组合，再决定是否需要 GNN。优化目标不能只奖励输出更多对象；同时惩罚错角色、错 owner 和没有独立图像证据的重复使用。

T03 将局部重识别从“普遍 scale2”改为缺字段/角色冲突触发：器件位号缺失看框外邻域，pin 编号缺失看侧边条带，IC 型号/长引脚名缺失看完整行或器件内部。只用相邻框和图像提出更完整 crop，再重新识别；不直接拼字符串补缺字。0/90/270 度、原尺度/2 倍先做少量配对消融，按原图投影统一坐标。保留大小写和原始字符串；`10k`、`10K`、`10 k` 分别记录。

建议增加“预期恢复对象数/耗时”的重识别排序：缺一个位号可能使一整个 IC 的已观测引脚被裁剪，优先处理它通常比重复识别一个孤立值更有潜力。这是调度假设，收益估计仅用训练数据和当前预测特征；不读取评测 GT。保留少量探索配额，防止只照顾高密度 IC。

T04 分开校准识别、角色、owner 三类分数，画 precision–coverage 与 risk–coverage。实际训练输入保持预测 ROI、错字和断裂，不把 GT 字符串或 owner 插入输入；正负例必须来自真实候选池，含糊对应 masked。器件型号和 pin 角色补充困难负例，控制同一 GT 对应多个 OCR 观测的权重。只有高覆盖、角色约束仍不足时才考虑再训练更复杂模型。

验收：两例回退必须给出图像解释和回归；正确 key 不低于核验后的 Bdev，同时缺 key 裁剪数下降；pin 编号、pin 名、型号和值分别报告，不能用一项抵消另一项。建议首轮目标是缺 key 裁剪减少 20%，这是待测目标；若仅增加非空字段、错误 key 上升则拒绝候选。

涉及：`association/text_component.py`、`semantic_fields.py`、`text_pin.py`、`pin_assignment.py`、`perception/ocr_multilevel.py` 和 `ocr_association` 诊断。新增分数与证据仅进入内部 IR/报告。

**6. component：优化能保留下来的小目标和框质量（T05）**

冻结 YOLO26l 候选权重，先分解漏检为小目标、tile 边缘、合并/NMS、类别混淆、框偏差、输出候选过滤。mAP/IoU 外，必须检查指南口径的框坐标误差回归；框变化会改变 OCR 邻域和 pin ROI，因此检测改进需要测后续身份留存。

先用现有切片实现比较两种有依据的增量：边界截断框触发邻片补看；按目标尺度触发细片，限制全图重复扫描。候选融合必须保护相邻小电阻/电容，不仅优化去重数。训练只在误差确实来自感知时启动：train240 困难 tile 重采样、缩放与线宽/颜色扰动，保持原 group 和标注一致。OCR 使用的文字不做破坏字符语义的镜像增强。

建议首轮目标：小目标/边界子集 recall 提高 3 个百分点、总体 precision 下降不超过 1 个百分点，并且最终正确组件身份不下降。未改善最终输出时保留 detector 候选供研究，不晋级。128 个候选上限此前未卡住这批开发图，只有新账本证明确实截断才调整。

**7. pin：让模型看到真实器件框，并引入有图像依据的几何补充（T06、T07）**

T06 训练/验证使用真实预测 ROI 与训练图 GT 的离线监督对应，分别记录“GT 框条件定位”和“预测框定位”，后者决定上线。当前 adapter 已有 offset 输出，不把亚像素预测作为尚未实现的新功能；重点查 resize/stride/offset 到原图的误差、边界 NMS、密集相邻 pin 和 owner 错配。不要重启已撤回的 budget 单位修复。

优先复用已有 Pin32 真实训练 ROI 产物，检查它是否覆盖当前 detector/先验/阈值和密集场景。单次训练只改变一种因素：困难 ROI 采样或预测框扰动。保留有限梯度、正样本构造、训练/验证一致性检查。固定当前端到端较好的候选阈值与边界带作为对照；训练门槛不得为了通过而下降。

T07 借鉴 SINA，提出由实际骨架端点/线与器件边界交会支持的 pin 候选，与热图、方向和局部灰度共同筛选。文字掩膜可能擦掉真实 pin/导线，所以同时保留原始分支及端点保护带；候选只有坐标和依据，编号/名称仍来自可见 OCR。两脚器件、密集 IC 和连接器分开评价。

建议验收：预测 ROI 的原图 5px recall 提高 5 个百分点且 precision 不明显退化；最终可输出正确 pin 数提高，字段和网络不下降。GT ROI F1 上升而最终输出下降属于失败。几何融合若只增加线端点 FP，关闭该分支并保留失败例。

**8. wire：先查低精度来自哪一层，再训练（T08、T09）**

T08 为同图输出四份离线比对：原始概率掩膜、阈值/后处理掩膜、向量化折线栅格、最终所属 net 的线段栅格。统一原图变换、线宽、容差和 valid mask，核验 GT 标注覆盖。生产锁中的约 94% centerline F1 与当前约 50% raw 线像素 F1 不是同口径，不能直接推断模型退化。

将 FP 分类为文字笔画、器件外框、重复折线、形态闭合桥接、pin snap 产生的额外线、坐标/栅格口径误差、GT 缺标。先抽查训练图和固定开发失败集中的样本，若主要是栅格口径就修评估并版本化，若是桥接就改后处理，若原始 mask 已错才进入 T09。

T09 复用现有 BCE/Dice/soft-clDice，围绕真实困难负例做有界消融：文字、器件边框和近邻平行线负例提高采样，保护真实交会和端点。不要将所有 OCR bbox 都硬置零，不要盲目加大 close 半径。已有颜色过滤仅适用于可支持的颜色分布，黑白图单列回退路径。

建议首轮目标：统一口径后线像素 precision 提升 5 个百分点、recall 下降不超过 1 个百分点，同时实际连接断裂和误并均不增加。损失下降但端点/网络恶化则淘汰。clDice 的二维连通偏好可能强化非电气连接交叉，需通过下一节通道语义约束解决。

**9. Physical Graph、Electrical Net 与线段：连接必须可解释（T10、T11）**

T10 先按连接证据类型统计 false union 和 missed union：端点接触、同源折线、junction、虚拟修补、pin snap。保留现有共享 `collect_segment_connections`，让建图与 Validator 使用同一证据定义。重点审查无点交叉、T 点、带点十字、桥形跨线、近邻平行线、器件框交会等局部区域。

对无连接交叉，候选以“进入方向→允许离开方向”的关系表示：同一像素位置可以有多条互不连接的通道。带点连接需允许多方向合并。先改确定性规则和局部证据，暂不新增第五个 junction 模型；若后续引入学习型 junction，必须走现有配置开关与五任务完整晋级契约。

pin snap 同时考虑原图距离、pin 朝向、附近多个线的竞争及实际像素支持，不只取最近线。gap repair 限制到同方向、可见路径支持且不存在竞争导线的局部；所有虚拟修补保留来源和预算。不得用“电路应该连通”推断真实连线。

T11 将网络指标拆成两个视角：固定可用 pin 的拓扑质量，以及全部真实 pin 的端到端质量。上游漏 pin 很多时，第一个视角让 Graph 模块仍可量化进展，第二个视角防止掩盖漏检。只在独立离线诊断中使用 oracle 替换，标记 `oracle=true`，不混入候选或晋级证据；尽量先用不改预测的条件评估。

Electrical Net 单独审计信号标签误并、标签作用域、层级/总线表达；规则不明确时保留歧义，不能默认全局同名即同网。power/ground 合并继续按有效配置执行。网络的 pin set、线段来源、线段端点和所属网络必须一起复算，避免只改 junction 而保留旧图。

建议首轮目标：固定可用 pin 子集的连接 precision 提升 5 个百分点，recall 不退化；每个采样 false merge/false split 都能定位到证据。匹配网络内再看线段两端点的 5px 回归，不能用整图线像素高分代替 NetLineF1。全量四项指南回归必须并列，raw-v1 仍作诊断。

**10. Validator、输出、运行时与晋级：把模块进展交付出来（T12–T14）**

T12 保持严格 Validator 0 ERROR。增加“合法性”和“完整性”两份报告：前者决定能否序列化，后者说明为什么丢失多少对象。继续区分 strict_success、degraded_nonempty、fallback_empty。缺 key/number 不自动编号，不用占位值，顶层始终只有 components/pins/nets。

合同回归覆盖角色更新后图重建、裁剪原因闭合、重复可见位号、来源折线去重、禁止跨通道误连、相同输入/配置 JSON 字节确定。只为实际变更增加有意义的测试；实现后先 unit 后 integration，缺依赖/夹具与代码失败分别记录，不把 skipped 当 passed。

T13 将服务器快速 CTC、mask 缓存的已验证候选移植为独立 feature flag，先做同输入等价检查。CTC 保留维度、全量有限值/概率范围、blank/repeat 和置信计算合同；不能只验证获胜类别而漏掉其他位置的 NaN/Inf。局部解码加速不宣称整图同倍加速。

之后用 ORT profiling 区分 Session.run、H2D/D2H、CPU 后处理和调度。若大字典输出复制仍占主导，再试图内输出索引/分数与有效性状态；这是新图导出，需要完整 lineage、错误合同和真实 OCR/最终 JSON 比对。I/O Binding 之后还把全部 logits 拉回 NumPy 会削弱收益。长宽分桶先于 CUDA Graph；后者要求兼容算子、固定形状/地址及 session 并发限制，不能直接套用到现有多 worker。

服务器 8 worker、每 worker 2 线程只是历史已测设置，不自动视为当前最佳配置。运行前检查实际资源和 GPU lease，训练仍单 GPU 串行。可评估一个常驻 GPU 感知服务配合有界 CPU 图队列，减少多份模型，但仅当画像证明重复模型/显存或调度是瓶颈再实施。Windows CUDA fallback 不作为 GPU 预算证据。

建议性能候选门槛：5 轮配对交替运行，分别报告冷启动、预热、稳态、P50/P95/max、全批墙钟、峰值显存和真实 provider；目标全批中位耗时下降至少 10%，结果字节一致。共享负载严重时标记结论不确定。每图仍≤600s，实际生产批次≤有效批次预算；30 张不能冒充正式全量预算证明。

T14 最后才整理候选 bundle、哈希、lineage、模型卡、导出一致性、端到端质量和预算证据，经 `data_tools.model_promotion` 生成新候选锁并验证。若 Pin32 等原有训练门槛未通过，保持 candidate；后校准指标不能改写原 gate_failed。若关联器引入额外可学习权重，须补齐其配置/hash/许可/lineage 契约，不能作为未追踪旁路资产，也不手改 blessed/status。

**11. 建议执行节奏：约 10–14 个工作日的首轮，按证据调整**

以下是单人实施量级估计，不是训练时长承诺。各模块在前期完成诊断和实验准备，GPU 训练按队列串行。本次未启动任何任务或子 agent。

| 阶段 | 工作 | 必须交付 |
|---|---|---|
| 第 1–2 天 | T00/T01 基线与账本；复核 key 回退；T08 导线四层误差剖析；T12 指标契约 | 各模块错误分布、两条基线、冻结输入和可复现命令 |
| 第 3–4 天 | T02 跨角色竞争、T03 定向重识别、T04 校准；T05 检测分层实验 | 正确 key/pin 字段增量及全部回退例，检测消融 |
| 第 5–7 天 | T06/T07 预测 ROI 与几何 pin；若 T08 支持再做 T09 wire 训练 | 原图 5px pin、最终存活、wire precision/recall 与网络影响 |
| 第 8–10 天 | T10/T11 通道交叉、snap 和网络/线段；T13 已证性能优化集成 | 条件拓扑改善、匹配网内线端点、字节等价及耗时分布 |
| 第 11–14 天 | 小型交互消融、全新推理、T12 完整测试与 T14 晋级审查 | 实测组合版本、失败/淘汰列表、回滚配置；有完整证据才晋级 |

优先资源分配建议：约 40% 用于 OCR/association，20% pin，20% wire/graph/nets，10% component，10% 运行时/评估。数据账本贯穿所有任务，不把每个模块平均投入 GPU 时间。

交互实验只选主要组合：Bdev、+角色竞争、+定向重识别、两者合并；通过后再加 pin，最后加 wire/graph。每次使用同样输入、模型、阈值、随机种子与指标定义，只改变声明因素。冻结感知适合 association 消融；涉及 ROI、detector、pin 或 OCR 本身变化必须重新推理，不能复用失效缓存。最终组合必须四模型 fresh inference，才认定端到端改善。

**12. 统一停止条件与最终交付**

单个假设最多先做两轮有明确差异的试验。若没有目标指标增益，或增益来自错误字段/误并网增加，则归档失败原因，转下一个已排序假设；不持续全量扫参。性能候选要求语义等价；质量候选允许输出改变，但必须解释每类改变及回退。

每项任务交付代码或可运行诊断、输入/代码/模型哈希、复现命令、同口径对照、失败案例、feature flag/回滚路径。状态分别为 proposed、implemented、validated、rejected、blocked，不能用“整体完成度”取代证据。这里“各模块有进展”意味着每个模块至少完成可复核的瓶颈分解和一个有结论的实验；不保证所有模块在同一轮都获得正增益。

四项各≥95%仍可作为长期目标，但现有 raw-v1 和暴露过的开发集无法证明已接近它。近期合理目标是显著提高真实身份留存、在固定可用 pin 上改善拓扑，再逐阶段提高完整输出正确性。官方 evaluator 到位后，另行建立正式验收；此前所有指南实现均标记为本地回归。
