# 大容量 YOLO 与 OCR：候选及验证约定

检索日期：2026-10-02。用户明确要求试验更大的 YOLO/OCR，并追加 YOLO26。
验收目标仍是器件、引脚、网络、线段四项分别 ≥95%；官方评测器尚未获得。

## 选择的模型

|候选|官方通用检测指标/文件规模|本项目试验用途|
|---|---|---|
|YOLO11l|COCO mAP50–95 53.4，25.3M 参数；现有 YOLO11n 为 39.5、2.6M。|与现有 nano 检测器比较容量变化。原理图类别必须重新训练，不能直接使用 COCO 类别。|
|YOLO26l|COCO mAP50–95 55.0，融合推理参数约 24.8M。保留完整训练结构的当前权重实际为 26,299,704 参数。|与 YOLO11l 使用同一数据、相同切图、训练和评测条件，比较架构变化。|
|PP-OCRv6 medium det + rec|官方 ONNX 检测权重 62,032,837 bytes，识别权重 76,554,979 bytes。|与现有 PP-OCRv5 mobile 英文识别方案做原图 OCR 对照。保留几何候选，分别检查文字、绑定字段和最终网络。|

来源：[YOLO11 官方文档](https://docs.ultralytics.com/models/yolo11/)、[YOLO26 官方文档](https://docs.ultralytics.com/models/yolo26/)、[PP-OCRv6 官方介绍](https://www.paddleocr.ai/latest/en/version3.x/algorithm/PP-OCRv6/PP-OCRv6.html)、[官方 det ONNX](https://huggingface.co/PaddlePaddle/PP-OCRv6_medium_det_onnx)、[官方 rec ONNX](https://huggingface.co/PaddlePaddle/PP-OCRv6_medium_rec_onnx)。

以上数字来自通用数据集或官方内部评测，不能代替本赛题准确率。没有下载 LLM/VLM。
PP-OCRv5 server 也可作为后续候选，本轮先验证更新的 v6 medium，避免堆积模型。

## 数据与训练比较

使用 dataset300-v2 的固定 grouped split：240 train / 30 val，训练不传输 test。
复用现有可追溯的组件切图：1417 train tiles / 190 val tiles，34 类，640px、96px 重叠。
原始训练预检通过；旧导出目录的完整文件集验证因新增两个 Ultralytics `.cache` 文件失败。
本次没有重写旧 inventory，而是逐项核验原始组件文件哈希，排除缓存，建立新的传输绑定。
所有原始 source manifest / split / component / text manifest 的哈希也重新核验。
`transfer-binding.json` 明确记录这一差异，不能声称旧目录完整验证通过。

YOLO11l 与 YOLO26l 使用相同基线参数：640px、batch 8、最多 120 epochs、patience 20、
AdamW、相同学习率与增强、seed 20260912。先各自完成一轮小比例 GPU smoke，再正式训练。
正式训练只保留必要的 best/last，不产生周期检查点。
Ultralytics 的默认 AMP 检查会下载另一个 YOLO26n；本实验改为核验实际候选网络的 FP32/AMP
输出与有限值，再由实际训练 smoke 检查损失。检查范围及误差写入训练状态文件。

旧 YOLO11n 已训练权重仅作同数据基线，不属于当前生产模型锁。
历史训练硬件与框架有差异，最终应在同一远程运行时复核两种大模型与 nano 的结果，
不能只比较历史日志中的 mAP。

## OCR 比较与当前证据

v6 官方字典包含 18,708 个字符，加 CTC blank 和空格后，模型输出为 18,710 类。
现有适配器原上限 16,384，已扩至有界的 32,768，同时保留单字符、去重、输出维度、
文件哈希及描述符大小校验。针对大字典末尾类别、重复字符、越界与维度不匹配的测试通过；
字典扩容时完整测试为 **810 通过、71 跳过、0 失败**。
真实 ONNX 模型输入高度 48，输出类别数与字典严格一致。生产锁与配置未修改。

0062 首张远程 GPU smoke 已完成，控制/候选均严格 0 ERROR，控制输出与 GPU 基线字节一致。
首轮完整 30 张 OCR 对照已结束：控制 30/30 成功，候选 26/30 成功、4 张失败
（0140、0155、0171、0190），所有案例均保留在 predictions/error manifest。
该轮退出码为 1，不能只对成功子集报告总体准确率或晋级。
OCR 实验重新读取原图运行新模型，组件、引脚与线段几何来自已绑定的 GPU 感知结果；
这是单项替换实验，不能描述成完整四模型重新推理或官方竞赛成绩。
新版实验同时更新模型版本元数据，避免继承旧 OCR 版本造成误标。

0140 的原图诊断复现了失败：4×20px 小 ROI 的四边形还原后为
`[[1,0],[12,0],[12,0],[1,0]]`，裁剪高度为 0。
DB 后处理原来只在检测坐标检查尺寸，缺少缩放/舍入/裁边后的几何检查。
已增加源像素空间的零尺寸/零面积过滤，保持有效的 1px 小裁剪，
`crop_quad` 对直接非法输入仍抛错，时间预算与模型输出检查也保留。
针对实际退化框、转置方向及有效微小裁剪的测试通过；完整回归为
**812 通过、71 跳过、0 失败**。
参考 [PaddleOCR 官方后处理](https://github.com/PaddlePaddle/PaddleOCR/blob/main/tools/infer/predict_det.py)
也在源图坐标裁边后过滤微小框；本次仅排除不能裁剪的退化几何，未引入官方的 3px 过滤阈值。
服务器已在上轮结束、GPU1 空闲后部署这一修复；重新执行全 30 张，结果单独写入
`ocr-medium-val30-cropfix`，保留首轮失败及输入绑定。

`run_serial_large_trials_v2.py` 负责 GPU1 串行看护，顺序为 YOLO11l smoke → YOLO26l smoke
→ OCR 修复后的全批 → YOLO11l 正式训练 → YOLO26l 正式训练。
任一步失败或输入哈希改变会停止后续任务。
YOLO11l / YOLO26l GPU smoke 均已通过（各 1 epoch、exit 0），所有记录的训练/验证损失为有限值。
两种模型的实际候选 AMP 比较均未满足保守的误差门槛，因此 smoke 使用 FP32；
不能把配置中的 `amp=true` 描述为已启用混合精度。正式训练将再次记录这一检查结果。
Ultralytics 在 smoke 的最后一轮仍保存了 best/last，即使设置了 `save=false`。
已在两个 smoke 进程结束后核验四个文件哈希并删除，只保留状态/日志/CSV及删除证据，
回收 **208,622,816 bytes**。这次清理仅涉及新产生的 smoke 权重，先前被拒绝的目标未删除。
正式训练结果尚不可引用。

已准备并排队训练后的原图比较：同一远程运行时、固定旧检测协议 512/64、score 0.20、
NMS 0.55、全图最多 128 个候选，依次比较已有 YOLO11n、YOLO11l、YOLO26l。
使用既有坐标恢复/跨切图 NMS 实现；推理过程只读 30 张原图和静态类别表，禁止标签访问。

## 晋级前需要的证据

1. 三个检测器在相同原图上按统一切图恢复坐标，并报告各类别 P/R、误检和漏检。
2. OCR 在同一批原图、相同 ROI/阈值下比较；另将识别器替换与整套 OCR 替换分开，定位收益来源。
3. 接入完整流水线后核验位号、型号、引脚编号/名称及 owner，再复核网络与线段。
4. Validator 0 ERROR、官方 JSON 字节确定、所有选中案例计数；检查 600s/图与 7200s/批。
5. 完整 candidate bundle 与真实 lineage/评测证据齐备后，才可通过 model_promotion 晋级。
   外部 OCR 未在 v2 上训练，不能伪造训练 lineage；本轮保持为开发候选。
