# 系统优化迭代记录与四项 95% 目标路线

截至第二轮，身份字段缺失仍是最大的输出损失来源，引脚检测和导线拓扑也存在独立瓶颈。完整 OCR 明显改善字段恢复，其 ONNX 后端已在 30 图严格回放中保持最终 JSON 字节一致并缩短 OCR 耗时；可移植前后处理尚未完成。引脚边界和整框删线实验均未达到采用条件。四项分别 ≥95% 尚未达到，生产模型锁保持原样。按用户要求，已删除 193 个多余权重和检查点，释放约 7.34 GB。

用户已确认：官方评测器尚未获得，继续按照赛题指南做开发验证。以下数值均标注其实际口径，不能换算成竞赛成绩。验收目标没有改为加权平均 ≥95%。

## 1. 指南约束与当前验证方式

依据：[赛题六官方指南](E:/EDA挑战题目六/artifacts/reference/2026_EDA_Challenge_Task6_AI_PCB_Schematic_Official_Guide.pdf)。指南四项为 ComponentF1、PinF1、NetHypergraphF1、NetLineF1，权重分别为 30%、25%、35%、10%；器件框容差 20px，引脚及线段容差 5px。输出要求及身份字段会影响是否匹配成功，单独检测到图形不代表这一项正确。

当前有两类本地评估：

- `raw-v1`：用于定位器件几何、引脚几何、字段、连通性和导线覆盖的损失。本报告中的几何 F1、成对连通性 F1、像素线覆盖 F1 都属于这一类。
- `guide-v1`：按指南假设实现的 JSON 回归器，仍需核对类别别名、缺失身份、网络匹配顺序和汇总规则。它不是官方 evaluator，不能把其 weighted_score 当竞赛成绩。

正式开发验收应保留四项独立门槛、所有选中案例和契约覆盖率。失败、超时、未运行案例不能从分母消失；也不能仅在“可评字段”上达到 95% 就宣布整套系统达标。官方评测器到位后，需要用固定预测文件再做一次正式核验。

## 2. 本轮基线是完整图像推理

使用主锁 `models/models.lock.json`、`configs/pipeline.edarace.yaml` 和 `competition` profile，完成 Dataset300 的 30 张开发验证图，覆盖 29 个重复组。逐图推理不读标注；标注只在离线评分时打开。

30/30 运行成功，全部为 `degraded_nonempty`，没有 `strict_success`。总耗时 2915.5s，约 48.6 分钟；逐图 P95 为 235.9s，最大 511.1s。这是本机 CPU/CPU fallback 结果，不是 GPU 时延或官方 Docker 50 图整批性能证明。

### 裁剪前后的损失

| raw-v1 本地诊断 | 裁剪前 | 严格序列化前的最终 IR |
|---|---:|---:|
| 器件几何 F1 | 80.62% | 25.70% |
| 引脚几何 F1 | 59.14% | 12.63% |
| 器件匹配 TP | 913 | 166 |
| 引脚匹配 TP | 1611 | 183 |
| 文字、字段、归属同时正确 | 121/1975 | 85/1975 |

裁剪前有 1197 个引脚误检、1029 个引脚漏检。最终器件和引脚的大量损失来自缺少可观测、可靠绑定的位号或引脚编号，不能靠放宽 Validator 或自动编号修复。

基线 OCR 在 1975 个有位置的 GT 字段框中匹配到 977 个，感知阶段准确识别 295 个。20,000 左右的未匹配 OCR 输出不能全部判成误检：GT 只覆盖字段文本，并不覆盖图上所有文字；但其数量和 detector 白图响应表明，当前检测器需要检查噪声与分组质量。

### 网络问题不能全部归因于裁剪

在离线诊断中保留所有原始几何对象、跳过身份裁剪，用同一配置构建 Physical Graph 和 Electrical Net，得到成对连通性 TP=608、FP=1155、FN=2652，F1=24.21%。构图阶段不读取 GT，随后才离线评分；这一结果不允许序列化或充当发布证据。

最终基线的成对连通性 F1 为 0.54%。它同时受身份裁剪和真实拓扑误差影响。导线像素覆盖召回率 94.47%，精确率仅 33.58%，F1=49.54%。优先清理符号、文字和图框造成的错误导线，并分析误并来源，比单纯扩大吸附和断线修补半径更有依据。这里的两种 F1 都不是指南的网络/线段指标。

## 3. 已完成的修复与效果

### 可执行修复

1. 为推理产出增加 `perception`、`association`、`pre_prune`、`final` 四阶段快照及哈希绑定，将执行成功与输出质量分开统计。`pre_prune` 在构图之前，因此不能用它的零连通性数值评价网络。
2. Paddle recognizer 支持批量调用、同批去重和有界缓存；修复灰度裁剪与三通道输入的接口不一致，保留顺序和数量，失败结果不进缓存。
3. 向逐图上下文传入整批共享 deadline，在组件批次和 OCR 批次边界检查剩余预算。当前仍是协作式检查，不能保证中断正在阻塞的第三方调用。
4. 保护已符合语法的 OCR 原文假设，例如 GAIN1、VDD1、PB10、CSN2、VOUT2G，避免后处理把前缀中的字母改为数字；两种微单位字符也能经过 NFKC 正常识别。
5. 未归属的纯数字不能仅凭靠近线条就被推断为网络名，减少短数字跨网络误并风险。明确提供 netlabel 语义的数字仍保留；附近有引脚几何证据时仍按 pinnumber 处理。
6. 增加可选、强制 SHA256 绑定的静态型号目录。只有实际器件正文框内、精确命中且不属于常规位号的型号才进入 searchname。主生产配置未启用该目录。
7. 冻结感知的回放脚本补齐 production profile 与推理源码哈希记录，避免把配置不同的对照混为同一个运行。

有效位号前缀修复将基线关联阶段的准确识别数从 287 恢复到 294；最终联合字段仍是 85。纯数字保护及前缀修复后，30 张基线的官方格式 JSON 均与原输出字节相同。这些是接口、假设保护和风险修复，不能宣称已经提高了当前基线的最终成绩。

冻结几何不变，器件/引脚最终几何 F1 的变化来自身份恢复后保留了更多对象。OCR 本身改善明显，但网络精确率从 13.85% 降到 7.35%，误连通对数从 56 增到 227。更多编号进入构图会暴露已有错误，不能仅凭召回上升晋级。

完整 OCR 对照采用本轮修复后的下游代码；同版本代码对原始感知的控制回放中，30 张最终 JSON 字节均与基线相同。因此最终输出的改善可以区分于这些接口修复；表中的关联阶段基线仍为原始运行数值。

### 器件候选的负面结果

在相同配置、相同 5 张图和相同完整 OCR/导线证据下，现有 YOLO v2 器件候选重新产生器件框及引脚 ROI，最终器件几何 F1 从 34.48% 升到 38.98%，但引脚几何 F1 从 18.62% 降到 10.90%，编号正确数从 20/92 降到 10/92，网络无改善。

因此不晋级该候选。此结果只约束这组配置和 5 图对照，不能推断 YOLO 在所有配置下均劣于 RCNN。后续必须联动验证框定义、裁剪上下文、缩放、类别表和 Pin prior，不能根据旧单模块成绩直接替换主锁。

## 4. 优化路线与每步验收

| 优先级 | 具体工作 | 必须提交的验收证据 |
|---|---|---|
| P0：契约和测量 | 固定指南字段、类型映射、坐标、重复位号、缺失编号和网络匹配假设；对四项输出保留覆盖率与不可比较项 | 版本化契约差异表；四项独立结果；所有案例状态；与原始 target 的可追溯差异 |
| P0：完整 OCR 接入 | 为胜出的检测+识别组合构建可离线加载的完整 OCR candidate bundle，绑定权重、字典、预处理、推理参数、许可证与来源；不要让用户缓存成为未记录的生产依赖 | 冻结原图字段比较；高分辨率小字/旋转字分域结果；正式图像入口的完整推理；导出一致性和模型加载证据 |
| P0：字段与归属 | 以真实 token、器件框、引脚、方向和行列结构联合判断 designator/value/searchname/pinnumber/pinname/netlabel；已有一对一匹配继续复用；候选置信度和拒绝原因可追溯 | 文字准确×字段正确×归属正确的联合指标；误绑迁移表；缺身份裁剪的对象数下降，且错误身份不增加 |
| P1：器件与引脚联动 | 对组件尺寸/长宽比/边界偏差和各类 Pin ROI 分层；核对训练与推理的 bbox 定义及 decoder prior；需要训练时只用 v2 train 240，先 preflight 和 smoke，单 GPU 串行 | 同配置 A/B；原图 5px 引脚定位、漏检和误检；编号绑定；最终 Pin 与网络同步提升，而不是只提高点检出率 |
| P1：导线与拓扑 | 将器件正文、文本笔画、边框和真实导线的错误拆开；保留可观测端点/分支；分别记录 pin snap、crossing、gap repair、同名标签误并；按误并对数和断网数选择修改 | 固定图像的图结构 A/B；逐类 TP/FP/FN；虚拟修补比例；网络及线段均改善；禁止任意增大距离阈值 |
| P1：严格批运行 | 为可能阻塞的模型/API 调用建立可终止的执行边界，覆盖加载、排队、推理、输出、末例和失败处理；官方环境验证 CPU/GPU 与导出后端 | 真实 submission 入口的整批演练；600s/图与7200s/批的完整计时；GPU P95；失败清单；JSON 字节确定性 |
| P2：局部推理辅助 | 只对几何支持明确但仍有冲突的局部字段/交点启用已有选择性推理机制，记录单次净救回与错误迁移 | 字段和网络的配对收益、耗时与 token 成本；离线缓存、失败回退与预算；未经授权不启动付费远程批任务 |

优化次序：先完成 OCR 组合的可复现接入及字段绑定，再联动器件/引脚，并根据错误连通证据修改导线与构图。网络占指南 35%，必须作为共同门槛；不将第五个 Junction 模型或整图大模型生成作为默认下一步。

每一步都保留上一组完整配置和模型锁。若候选仅增加非空率、引入错误身份、增加误并、依赖 GT 或无法离线加载，则不晋级；候选只有通过现有 promotion 工具生成新锁。四项分别 95% 是目标，不是本报告推测可保证的效果。

## 5. 数据与可解释性边界

这组 30 图属于已暴露的开发回归，不是独立泛化证明。公开 210 图与 Dataset300 存在精确字节重复；release50 也不能当新 holdout。

后续新增数据先做字节/结构去重和来源复核。训练范围仍限 dataset300-v2；若得到新的独立验证图，先冻结方案再评估，一旦据其调参即记录为暴露数据。

### 物理误并与器件框删线

## 12. 第六轮：用图像颜色证据减少符号笔画误连

验证日期：2026-10-01。方法检索提出符号/文字与真实导线分离后，本轮实现一个轻量的彩图过滤器。它利用已感知引脚的方向，在器件框外采样原图颜色；至少 6 个引脚、3 个器件、75% 一致支持才接受导线主色。只删除图像上有充分彩色笔画、而几乎没有导线主色支持的候选线段。灰度图及颜色证据不足的图自动回退。没有固定指定绿色、没有使用数据集来源或样本 ID，也没有读取标注。
