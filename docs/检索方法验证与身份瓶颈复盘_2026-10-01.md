# 检索方法验证与身份瓶颈复盘

2026-10-01，第七轮开发验证。结论是优先打通可靠 OCR 的生产验收，再做文字身份的联合绑定，随后改善引脚出口和交叉拓扑。外部方法值得借鉴，尚无证据证明替换现有系统即可达到器件、引脚、网络、线段四项各 95%。

前次完整检索见 [方法检索与路线](E:/EDA挑战题目六/docs/全网方法检索与优化路线更新_2026-10-01.md)。该文的生产配置与数据表是第五轮历史快照；当前生产使用第六轮轮廓过滤，本文以当前配置和第七轮证据为准。

## 适合本系统的外部方法

|顺序|方法与原始来源|具体迁移点及限制|
|---|---|---|
|1|[PCBnet 论文](https://arxiv.org/html/2608.27923v1)|文字定位、识别与器件上下文配对分开处理；先解决 OCR 已读对、字段或归属却错误的问题。论文报告文字准确率 98.57%、连接准确率 84.47%，两者均非本题四项指标。|
|2|[SINA 扩展版](https://arxiv.org/html/2607.01609v1)|去文字后的导线骨架端点与器件周边共同提出 pin 候选。其 95.3% 是坐标匹配的 Pin F1，未验证本题的编号、名称与归属。候选必须位于原图可见连接点；保留出口短线，避开整框清空。|
|3|[Image2Net](https://arxiv.org/html/2508.13157v1)、[Circuit Digitization](https://github.com/boscochanam/circuit-digitization)|区分 T 接点、带点交叉、平面交叉、跨线桥、pin tip 和符号边框；使用方向、线宽、原图墨迹及局部竞争约束吸附和缺口修复。优先抑制误并，再验证断线恢复。|
|4|[PP-OCRv6 官方说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv6/PP-OCRv6.md)|small 可作为后续单一 OCR 对照；先完成现有轻量候选的整批图像、真实来源、字典、目标 ORT 和预算验证。本轮没有下载新权重，未声称 v6 在 PCB 图上优于现有候选。|
|后续|[Netlistify 作者仓库](https://github.com/NYCU-AI-EDA/Netlistify)|若规则端点仍有明确上限，再对照直接预测导线端点和器件方向。原始官方 PDF 链接检索到但抓取解析失败，未引用其未核实精度数字。|

本轮再次检查 [PCBnet README](https://github.com/ECNUACRush/PCBnet/blob/main/README.md)：作者现明确说明受知识产权限制无法发布源码，并称提供 300 个演示样本。它不构成目前可直接运行的替换系统；与 Dataset300 的关系仍未核对，不作为新增 holdout。

新增核对 [OmniSch 论文](https://arxiv.org/html/2604.00270v1)及 [Microsoft Research 发布页](https://www.microsoft.com/en-us/research/publication/omnisch-a-multimodal-pcb-schematic-benchmark-for-structured-diagram-visual-reasoning/)：包含 1,854 张原理图，提供实体、图连接和几何推理评估。它可作为未来外部验证候选，但需先核对许可、样本重复和标注契约；本轮没有下载数据，也不将其加入训练。论文指出多模态模型在细粒度定位、全局连接及图解析上仍有明显不足。

TAM-GT 的 IEEE 检索结果涉及模拟电路网表与图同构，正文入口受到站点验证限制，未进入近期实现清单。PRISM 面向 PCB 双面实物图；向量 PDF 提取器依赖 PDF 图元，两者都不是当前仅图像输入的直接替代。

## 当前瓶颈与本地对照

以下全部是已暴露 grouped val30 上的 raw-v1 开发诊断。感知来自此前无 GT 的冻结预测，GT 仅供离线 scorer；不表示独立泛化或官方成绩。文字框 IoU、字段分类、owner 和最终字段采用各自诊断口径，不能把这些数量直接当成同一条单调漏斗。

|裁剪前文字诊断|主锁 OCR|未晋级独立 ONNX OCR|
|---|---:|---:|
|型号文字正确 /78|5|56|
|型号字段类型正确 /78|3|5|
|位号文字正确 /364|83|282|
|编号文字正确 /650|84|270|
|编号文字 owner 正确 /650|27|112|
|引脚名文字正确 /611|73|431|
|引脚名文字 owner 正确 /611|23|236|

这说明主锁存在识别覆盖问题，候选还存在严重字段分类与归属损失。型号 LM385 被当作位号、MCU 内部 PA2 被赋作器件 key，均是已有文字的语义冲突。局部距离阈值已难以同时解决这些错误。

开发原型使用精确静态型号库、可见 U/IC 位号、型号与位号的几何一致性和次优差距。相邻 R/C 位号不能支持 IC 身份；两个竞争位号或两个同样近的器件必须弃权。只从已有 OCR 原文给空 key 绑定，不生成 U1、引脚、编号或坐标；已有 key 与权威文本保持原状。静态库来自已绑定的器件库和历史开发补充，其匹配本身不证明身份正确。

30 图无字段正确数下降，无器件/引脚几何变化，无连接或导线指标回退。主锁 OCR 的 30 图无收益，输出 JSON 与第六轮控制逐字节一致。两条评分路径的汇总完全一致。两组仍全部为降级非空输出，schema 通过不能证明准确率达标。

早期原型 v1 的宽泛型号形状会误取 P3.4/T0 等引脚名：0065 编号正确数少 3，0095 引脚名正确数少 5，已拒绝。v2 虽只用静态库，仍误借 R3/C1 支持 IC 名称，0030 少一个匹配器件，已拒绝。v3 收紧支持位号后保留型号收益；v4/v5 对未绑定位号过于严格，没有额外输出收益。v6 增加独立的位号 owner 唯一性核对，恢复 0165、0171、0202 的三个正确位号。12 项针对缺位号、竞争位号、错 owner、内部引脚行、既有 key、权威文本和哈希失败的原型测试通过。

本轮只提交开发证据，未修改生产源码、配置或模型锁，未晋级模型，未进行训练或外部模型调用。该原型尚未在新原图完整四模型入口、目标 Docker 和独立样本上验证，暂不进入生产。

## 下一步完整实施顺序

1. 完成现有轻量 OCR 的真实来源和完整候选契约、目标 Docker ORT、整批四任务图像推理、重复运行确定性和 7200s 总预算验证。保持生产模型锁门禁；不把外部预训练资产描述成 dataset300-v2 训练产物。
2. 将本轮身份原型接入可消融的候选分支。以可见型号、标准位号、整侧编号/名称行和方向共同约束原有 Hungarian/有序 DP；分别测文字分类、owner、最终身份与裁剪损失。库中的不可见 pin 仍不生成。
3. 在保护真实引脚出口的前提下分离文字及符号笔画，用骨架端点辅助当前 pin 模型；随后逐项加入交叉类型、平行线竞争、可靠缺口和明确网络标签证据。观察最终网成员及网络内线段，不只看像素 F1。
4. 若现有 OCR 仍有明显识别上限，再仅对照 PP-OCRv6 small；若导线提取仍有明确上限，再做端点候选评分或负样本监督实验。训练只用 dataset300-v2 train240，单 GPU 串行，保留必要 best/resume，淘汰多余权重。
5. 按本地指南四项分别报告开发验证；取得官方 evaluator 后核验 ComponentF1、PinF1、NetHypergraphF1、NetLineF1，各项均须达到 0.95。不得用加权平均、坐标 F1、连接对或像素 F1 替代。

新模型副本为 0。删除本轮被替代推理快照的操作被自动审批拒绝，工具只返回 `blocked by policy`；没有重试删除，保留文件并使用压缩控制占用。模型清理偏好继续执行，不恢复已淘汰权重。
